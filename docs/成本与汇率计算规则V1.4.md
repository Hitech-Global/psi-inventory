## 0. 适用范围与禁止事项

本规则仅描述成本与汇率的计算口径、状态分离、金额分类、触发条件与生命周期，不涉及任何实现（代码、数据库表结构、接口、字段、页面）。所有落地动作待用户确认并进入 DB 设计阶段后再行实施。

## 1. 名词与范围

- **本国货币 LC**：按 CI 目的国计价的货币，即 IDR（印尼盾）、MYR（马来林吉特）、THB（泰铢）。
- **人民币 RMB**：系统中人民币记为 `RMB`（注意：系统不使用 `CNY` 标识，全系统统一用 `RMB`）。
- **USD**：常见外币。
- **成本确认 Cost Confirm**：`cost_confirmed = 1` 的业务状态，代表该 CI 库存成本已确定并锁定快照。
- **汇率快照 Snapshot**：在成本确认（或费用实际付款完成）时锁定的 `from → to` 汇率值 + 汇率日期 `rate_date`。
- **本币 WAC**：以本国货币计价的库存加权平均成本，存储于 `inventory.weighted_avg_cost`。
- **实时展示汇率**：系统「库存管理 → 库存总表」已存在的实时汇率功能，用于把当前本币库存货值换算成人民币，供中国团队查看当前库存规模。
- **CI 开启期 / 关闭期**：CI 在成本最终锁定且显式关闭前为「开启期（OPEN）」；满足关闭条件后为「关闭期（CLOSED）」。关闭后仍可能持有库存（A 类）或库存已清空（B 类），见 §25。
- **原库存导入**：`commercial_invoices.original_inventory_imported = 1`，代表该 CI 对应的实际入库数量已导入系统，可作为 WAC 基数。

## 2. 两类汇率（必须严格区分）

### 2.1 A. 成本汇率快照（Cost Rate Snapshot）

**用途**：CI 货值成本折算、费用成本折算、落地成本、本币 WAC、历史人民币成本、历史成本趋势。

**规则**
- 在成本确认（Cost Confirm）时锁定汇率值与汇率日期。
- 锁定后**不得随市场汇率变化**。
- **不得被库存总表实时汇率覆盖**。
- **不得回写或改变已确认的本币 WAC 和历史成本**。

### 2.2 B. 实时展示汇率（Real-time Display Rate）

**来源**：系统「库存管理 → 库存总表」已存在的实时汇率功能。

**用途**：库存总表当前人民币货值、当前本币库存价值换算成人民币、管理层查看当前人民币等值。

**规则**
- 可由系统自动获取最新汇率。
- 可以动态变化。
- 只用于展示和当前估值。
- **不参与 WAC**。
- **不改变历史人民币成本**。
- **不改变 CI 成本、费用成本或付款金额**。
- **不回写本币 WAC**。

> 关键结论：两类汇率并存。成本汇率快照负责「历史与成本」口径，实时展示汇率负责「当前估值展示」口径，二者互不覆盖、互不回写。

## 3. 两种人民币金额（必须严格区分）

### 3.1 A. 历史人民币成本（Historical RMB Cost）

- **含义**：本币成本按成本确认时锁定的汇率换算出的人民币成本。
- **用途**：历史采购成本、费用趋势、批次成本复盘。
- **特点**：历史稳定，**不随实时汇率变化**。

### 3.2 B. 当前人民币等值（Current RMB Equivalent）

- **含义**：当前本币库存价值按最新实时汇率折算出的人民币金额。
- **用途**：库存总表当前人民币货值、当前库存规模查看。
- **特点**：可以动态变化，**只用于展示**，**不作为 WAC 或历史成本依据**。

### 3.3 示例

| 项目 | 值 |
|------|----|
| 本币 WAC | 220,000 IDR |
| 成本确认汇率 | 1 RMB = 2,200 IDR |
| 历史人民币成本 | 100 RMB |
| 当前实时汇率 | 1 RMB = 2,300 IDR |
| 当前人民币等值 | 95.65 RMB |

两个结果都**可以**存在，但含义不同，**禁止互相覆盖**。

## 4. 七条原基线（V1.0，全部有效）

1. **本币成本本位**：库存成本以本国货币（LC）为本位记账，人民币为派生展示货币。
2. **成本确认驱动**：库存成本在 CI 成本确认（Cost Confirm）后确定，确认前为在途/暂估状态。
3. **本币 WAC 为本**：库存流转使用本币加权平均成本 `weighted_avg_cost`，不依赖实时汇率。
4. **人民币为派生**：人民币金额是基于汇率快照换算的统计值，非唯一成本依据。
5. **落地成本口径**：落地成本 = 货款 + 参与 WAC 的费用，统一以本币归集。
6. **费用归属明确**：费用是否计入落地成本（WAC）由 `include_in_landing_cost` 决定。
7. **汇率统一来源**：所有业务汇率统一读取 `exchange_rates` 表，已确认业务采用快照锁定。

## 5. 成本确认与付款状态分离（货款未付不阻止成本确认）

- 货款可能有账期，可分多期支付。
- **货款未付清不阻止成本确认**。
- CI 账单金额确定后即可作为货值。
- 成本确认时按锁定汇率折算成本币货值。
- 应付 / 已付 / 未付属于**财务付款状态**。
- 成本确认属于**库存成本状态**。
- 两者**必须分离**。
- 后续实际付款**不得重新修改已确认库存成本**。

> 分期付款含义：定金、尾款、多次补款等支付状态仅影响财务应付/已付/未付，不改变「货值以确定即可确认成本」的原则。

---

## 6. 汇率采用时点

- **货款成本折算汇率**：在**成本确认日**快照固化（**不是** CI 建立时，也**不是**任何一笔货款的付款日）。
- **费用成本折算汇率**：按**实际付款完成日（real payment completion date）**的汇率。
- **费用确认时间** = 实际付款完成（**不是**审批通过、**不是**申请日）。

---

## 7. 是否参与 WAC（include_in_landing_cost）

统一命名「是否参与 WAC」。

- **默认参与**：货款 / 国际运费 / 关税 / 商检 / 清关 / 本地杂费。
- **默认不参与（待最终确认）**：退款折扣 / 内部转账 / 银行手续费 / 不绑定 CI 的通用管理费。

规则：
- 参与 WAC 的费用进入落地成本与本币 WAC。
- 不参与 WAC 的费用仅作财务记账，不影响库存成本。

## 8. 本币 WAC 公式（两步法）

**禁止**写成：`landing_total_cost ÷ 本次入库数量 = 最终 WAC`

### 第一步：本次入库单位本币成本

```
本次入库单位本币成本
  = 本次 CI 本币落地总成本 ÷ 本次实际入库数量
```

### 第二步：新本币 WAC

```
新本币 WAC
  = （原库存数量 × 原本币 WAC + 本次入库数量 × 本次入库单位本币成本）
    ÷ （原库存数量 + 本次入库数量）
```

等价于：

```
新本币 WAC
  = （原库存本币总成本 + 本次入库本币总成本）
    ÷ （原库存数量 + 本次入库数量）
```

**必须明确**
- 本次入库单位成本 **≠** 最终 WAC。
- 必须使用**原库存数量**。
- 必须使用**原库存本币 WAC**。
- 当前库存导入已提供本国货币 WAC。
- 实时人民币汇率**不得参与**本币 WAC 计算。
- 补录费用 / 成本调整同样适用本两步法（对「当前库存」做增量重算，见 §17、§20、§24）。

## 9. 成本确认锁定规则（永久保存）

成本确认时锁定并永久保存以下信息：

- 原始金额、原始币种
- 汇率快照（from → to rate）、汇率日期（rate_date）
- 本币金额
- 是否参与 WAC（include_in_landing_cost）
- 确认人、确认时间
- 关联 CI、费用类型

锁定后永久保存，**不受后续汇率波动影响**。

---

## 10. 人民币成本冻结

- 人民币成本冻结的是**汇率快照**，属派生统计值，**非唯一成本依据**。
- 历史人民币成本按成本确认时锁定汇率换算，**不随实时汇率变化**。
- 当前人民币等值按实时展示汇率换算，**仅用于展示**。

---

## 11. 付款记录不可直接修改（冲销规则）

- 付款记录**不可直接改**，只可**冲销（红字）+ 重生成**。
- 冲销产生红字记录，重生成产生新正确记录。
- 冲销关联与原付款记录保持可追溯。
- 付款冲销只影响**财务付款状态**，**不触发 WAC 重算**，不修改已确认库存成本（若冲销导致货值需更正，走 §17 / §20 / §24 成本调整流程）。

---

## 12. 汇率自动获取与同步规则

- 系统通过第三方 API 自动同步汇率。
- 日常不依赖人工维护。
- 所有业务统一读取 `exchange_rates`。
- 成本计算过程中**不得临时直接请求第三方 API**。
- 支持自动补取历史日期汇率。
- 被业务采用的汇率**必须保存为快照**。
- 后续 API 汇率变化**不得影响已确认成本**。
- 库存总表现有实时汇率可使用最新自动汇率做**当前人民币等值**展示。
- 当成本所需快照日期缺失时的兜底原则，见 §19。

---

## 13. 历史 CI 财务维度与运营 WAC 存储隔离

- 历史 CI 的财务维度（人民币成本、费用明细）与运营 WAC **分开存储**。
- 运营 WAC 用于日常库存成本流转。
- 财务维度用于历史复盘与报表。
- 二者通过 CI / 批次关联，但**不互相回写**。
- 历史 CI 允许的操作范围与两类状态划分，见 §18、§25。

## 14. 四类金额区分总表

| 金额类型 | 汇率来源 | 是否动态 | 用途 | 是否参与 WAC |
|----------|----------|----------|------|--------------|
| 本币成本（LC） | 成本确认快照 | 否 | 库存成本、落地成本 | 是（参与） |
| 历史人民币成本 | 成本确认快照 | 否 | 历史采购成本、费用趋势、批次复盘 | 否（派生展示） |
| 当前人民币等值 | 实时展示汇率 | 是 | 库存总表当前货值、管理层查看 | 否（仅展示） |
| 付款金额（LC / 原币） | 费用=实际付款日汇率 | 否（锁定付款日） | 财务付款 | 不参与 |

## 15. 货款分期付款规则（V1.3，保持）

- **CI 账单金额确定即可参与成本确认**，不要求货款付清。
- **货款汇率快照采用「成本确认日」**（选项 ②），不采用最后一笔付款日（选项 ①）；「用户手动指定」（选项 ③）仅作汇率异常兜底（§19）。
- 若 CI 账单币种 = LC，货款直接入账无需换算；若 ≠ LC，按确认日快照折算为本币并锁定。
- 分期付款各笔汇率仅用于财务收付核算，不影响已锁定本币货值快照。

---

## 16. 多笔运费与多币种费用确认规则（V1.3，保持）

- 每笔费用在其**实际付款完成日各自确认**，按两步法**增量并入**落地成本与本币 WAC；不要求等全部费用完成再统一确认。
- 每笔运费按自身付款日快照折算本币（USD→LC / RMB→LC / 本币无换算），各自锁定互不影响。
- 每次新费用确认后按 §8 两步法对「当前库存」增量重算；CI 关闭后追加的费用按 §17 处理。

---

## 17. 补录费用规则（V1.3，保持）

- **允许进入原 CI 成本**，采用**「成本调整（前向）」**：新增成本调整记录关联原 CI，按 §8 两步法对当前库存增量重算新 WAC；已出库 / 已销售部分原 WAC 与历史人民币成本快照**保持不变**。
- 备选分支：若费用与本次到货无关或属期间管理费，进入**独立后续费用科目**，不参与该 CI 的 WAC，仅财务记账与分析。
- 补录费用同样适用 §7 的 `include_in_landing_cost` 判定。

---

## 18. 历史 CI 操作许可规则（V1.3，保持）

历史 CI **全部允许**进行：做付款、做核销、做费用（补录，按 §17 前向调整）、做汇率换算（用历史快照/补取历史汇率）、做成本分析。

**硬约束**：上述任何操作**不得影响**运营 WAC（`inventory.weighted_avg_cost`）、补货建议、订单预测、当前在库库存数量与价值、其他未关闭 CI 的成本。历史 CI 财务操作只产生财务维度结果 + 报表，绝不回写运营 WAC 与供应链预测。

> 两类历史 CI（库存>0 的 A 类 / 库存=0 的 B 类）的细化行为见 §25。

---

## 19. 实时汇率异常与成本汇率兜底规则（V1.3，保持）

- **严禁用「实时展示汇率」回填空缺的成本汇率快照**（两类汇率分离，§2）。
- 兜底层级：① 自动补取该日汇率 → ② 向前最近可用日近似（标记「近似兜底」）→ ③ 极端无可用汇率时**禁止自动确认成本**，转**人工确认**（手动指定汇率值+日期，标记「人工录入」）。
- 展示层降级（实时汇率异常）：库存总表当前人民币等值可暂显「—」或上次成功值，仅展示层降级，不阻断业务、不回写成本。

---

## 20. WAC 调整与重新确认规则（V1.3，保持）

- **优先「成本调整（前向）」，不重写历史 WAC**；**重确认（重写）仅限受控异常**且留版本痕迹。
- 分情形：补录费用→成本调整（§17）；付款冲销→只改财务不改成本；账单金额错误→小则成本调整、大且库存未大量出库则受控重确认并标注版本；汇率快照错误→按 §19 重算或成本调整。
- 任何 WAC 变更须记录：类型、原因、操作人、时间、原/新 WAC、关联 CI；历史 WAC / 历史人民币成本快照不可物理删除，仅追加版本。

---

## 21. 完整成本链路流程图（V1.3，保持）

```
采购
  ↓
PI（形式发票：确定供应商 / 付款条件 / 货值基准）
  ↓
CI（商业发票：确定账单金额 / 币种 → 货值以账单金额为准）
  ↓
费用（运费 / 关税 / 商检 / 清关 / 本地杂费，多笔多币种，按付款日各自确认）
  ↓
付款（分期：定金 / 尾款 / 补款；付款状态=财务维度，与成本分离；不可直改，只可冲销）
  ↓
成本确认（Cost Confirm：锁定货款汇率快照=确认日、费用汇率快照=付款日；永久保存）
  ↓
WAC（两步法增量重算本币加权平均成本；实时汇率不参与）
  ↓
库存（以本币 WAC 流转；历史 CI 操作不回写此处）
  ↓
人民币展示（双轨：历史人民币成本[快照，稳定] ＋ 当前人民币等值[实时汇率，仅展示]）
  ↓
利润分析（基于历史人民币成本做批次 / 费用 / 趋势分析；库存总表实时值供管理层看规模）
```

> 流程中「成本确认 / WAC / 库存」使用成本汇率快照；「人民币展示」中的当前人民币等值使用实时展示汇率，二者分离。

## 22. 《Cost Confirm 触发规则》（V1.4 新增 · 写死）

> 本章为成本系统最关键规则。Cost Confirm 是库存成本确定的唯一关口。

### 22.1 执行权限（谁可以执行）

- Cost Confirm 必须由具备专用权限 **`cost_confirm`** 的角色执行。
- 推荐初始授权范围：**admin**；是否授予 operator 或其他财务角色待 DB 阶段与权限模型一并确认（权限码 `cost_confirm` 本版仅作规则定义，不设计实现）。
- 无 `cost_confirm` 权限者不可触发成本确认；前端对应入口须按权限隐藏，后端须校验（与既有 `pi_confirm` 等守卫一致）。

### 22.2 前置条件（必须满足才可触发）

成本确认前必须全部满足：

1. **CI 单据已确定**：CI 已完成收货/入库，账单金额非空且币种合法（非停用/空币种）；CI 非草稿、非作废、非取消。
2. **原库存已导入**：`commercial_invoices.original_inventory_imported = 1`，即该 CI 实际入库数量已导入，可作为 WAC 基数。
3. **货款货值已确定**：CI 账单金额已确定（与分期支付状态无关，见 §5）。
4. **强制确认费用已确认**（推荐最小集，待最终确认）：**货款 + 国际运费 + 关税** 三项必须已在各自付款完成日确认并锁定汇率快照。理由：此三项为到货即定的主落地成本，缺失将导致 WAC 重大偏差。
5. **入库数量 > 0**：否则无法计算单位成本（见 §8 第一步）。
6. **汇率快照可得**：成本确认日快照可经 `exchange_rates` 取得，或已按 §19 兜底层级取得（近似/人工）并标记。

### 22.3 允许后补的费用（确认前可不确认）

以下参与 WAC 的费用**允许在 Cost Confirm 之后追加**（按 §17 前向成本调整，不阻断确认）：

- 本地杂费
- 商检费
- 清关费
- 其他到货后陆续发生或金额滞后的参与 WAC 费用
- 任何按 §17 定义的补录费用

> 原则：主到岸成本（货款/国际运费/关税）先确认，次要/滞后费用可后补；后补不要求重开 CI，按前向调整并入。

### 22.4 必须阻止的情形（Blockers）

任一满足则**禁止** Cost Confirm：

1. CI 账单金额未确定 / 币种非法 / 为空。
2. 原库存未导入（`original_inventory_imported ≠ 1`）。
3. 入库数量 = 0。
4. 强制确认费用（货款 / 国际运费 / 关税）中任一未确认或金额缺失。
5. CI 已作废 / 已取消 / 处于不可确认状态。
6. 该 CI **已存在生效的 Cost Confirm**（防重复；如需重算须走 §20 调整 / 受控重确认，不得二次直接确认）。
7. 成本确认日汇率快照无法取得且未走 §19 兜底 / 人工确认。
8. 关联 PI 处于系统定义的锁定态且禁止确认（若后续 PI 确认模块定义锁定理由，如已作废/下游锁定等，须在此处联动阻止；具体锁定清单由 L2A 确认模块提供，本版不预定义）。

### 22.5 确认后永久锁定的状态

Cost Confirm 成功后，以下**快照与状态永久锁定，不可回溯修改**（只允许前向成本调整 / 受控重确认，见 §20）：

- 货款本币货值（按确认日快照折算）。
- 已确认费用的本币金额与各自汇率快照。
- 成本确认日、确认人、确认权限来源。
- 确认时刻的「原库存数量 + 原本币 WAC」基数（作为快照引用，用于审计）。
- 本次入库单位本币成本、确认时刻 WAC 版本（v1）。
- 历史人民币成本（按确认日快照换算）。

> 注意区分：锁定的是**快照值**；WAC 本身可因后补费用按 §17/§20 前向增量变化（生成新版本），但已确认的快照不可被覆盖或回写。

## 23. 《CI 生命周期》（V1.4 新增 · 写死）

明确 CI 从创建到永久关闭的完整生命周期。

```
OPEN（开启）
  ↓  （账单确定 + 原库存导入 + 费用陆续确认 + 付款分期进行）
Cost Confirm（成本确认，锁定快照，见 §22）
  ↓  （补费用窗口开启：仍允许按 §17 前向调整）
是否仍允许补费用？ → 是（直至 Closed 前均可）
  ↓
Closed（关闭）
  ↓  （关闭后仍可做：付款 / 核销 / 补费用[前向，库存=0 时不溯运营] / 汇率换算 / 成本分析 / 利润分析）
```

### 23.1 OPEN（开启期）

- CI 创建、账单金额确定、库存导入、费用按付款日陆续确认（增量 WAC）、付款分期进行。
- 此阶段可做：费用确认、付款、付款冲销（仅财务）。
- 此阶段**尚未锁定**成本快照，WAC 随每次费用确认增量变化。

### 23.2 Cost Confirm

- 满足 §22.2 前置条件后，由 `cost_confirm` 权限者触发。
- 锁定 §22.5 所列快照，生成 WAC v1。

### 23.3 补费用窗口

- **Cost Confirm 之后、Closed 之前，仍允许补费用**（按 §17 前向成本调整）。
- 即：补费用不要求必须在确认前完成；确认后追加的费用继续增量重算 WAC（生成 v2、v3…）。

### 23.4 Closed（关闭）时机（写死）

CI 转 Closed 当且仅当满足以下之一：

1. **库存已清空且无可决补费用**：该 CI 关联批次剩余库存 = 0，且无未决/待补费用（或用户确认不再追加）。
2. **用户/系统显式关闭**：到货后经过设定观察期（如 N 天无新增费用）且用户手动标记 Closed；或用户基于业务判断主动关闭。

> 推荐以「库存=0 且无待补费用」为主关闭条件；显式关闭为管理兜底。关闭动作本身不改变已锁定快照，仅改变 CI 状态机。

### 23.5 Closed 后仍允许的动作

- 做付款（补付、冲销，仅财务维度）。
- 做核销（付款与应付匹配）。
- 做费用（补录，按 §17 前向调整；若库存=0，则调整只进历史成本分析，不影响运营 WAC，见 §24/§25）。
- 做汇率换算（用历史快照或补取历史汇率）。
- 做成本分析、利润分析。

### 23.6 Closed 后禁止的动作

- **禁止重新打开为 OPEN**。
- **禁止修改已锁定快照**（只允许前向成本调整 / 受控重确认，见 §20）。
- **禁止影响运营 WAC / 预测 / 采购建议 / 当前库存**（与 §18 一致；B 类历史 CI 尤其严格，见 §25）。

## 24. 《成本调整完善：已售库存规则》（V1.4 新增 · 写死）

> 本章完善 §17 / §20，明确「库存已卖掉一部分」时成本调整的行为边界。

### 24.1 核心原则（写死）

- **成本调整永远只影响当前库存（库存 > 0 部分）**。
- **已销售 / 已出库部分的原 WAC 与历史人民币成本快照保持不变**。
- **不得回写历史利润**：历史出库成本不可变，已入账利润不可被后续补费用修改。

### 24.2 公式（已售部分不参与基数）

补费用后的新 WAC 以「当前库存」为基数：

```
新 WAC
  = （当前库存本币总成本 + 补费用本币金额）
    ÷ 当前库存数量
```

- **当前库存数量** = 该 CI 关联批次的剩余在库数量（不含已售/已出库）。
- 已售部分既不参与分子也不参与分母，因此其历史成本不受影响。

### 24.3 库存 = 0 时的处理

- 若当前库存 = 0：补费用调整**仅记录为历史成本分析增量**，**不影响任何运营 WAC**（运营 WAC 已随最后出库转移/归零）。
- 该 CI 转为 §25 的 **B 类历史 CI**：补费用只进财务维度与历史利润复盘，不触运营。

### 24.4 利润分析口径

- 历史销售成本采用**销售当时的快照成本**（v1 或当时版本），补费用不修改已售批次成本。
- 补费用若针对已售部分，只在「该 CI 总成本复盘」中体现，**不修改已入账利润报表**。
- 当前在库部分的未来出库成本按新 WAC（v_n）计算。

## 25. 《历史 CI 两种状态》（V1.4 新增 · 写死）

> 本章细化 §18，将历史 CI 按剩余库存区分为 A / B 两类，明确各自行为。

### 25.1 判定依据

以该 CI 关联批次在 `inventory` 中的**剩余库存数量**是否为 0 区分：

- **剩余库存 > 0 → A 类**（历史 CI 仍持有库存）
- **剩余库存 = 0 → B 类**（历史 CI 库存已清空）

### 25.2 A 类：历史 CI 库存 > 0（仍参与当前库存成本）

- 行为：仍作为**运营 WAC 的构成来源之一**；其补费用（§17/§20/§24）的前向调整会**增量重算当前 WAC**，影响后续出库成本。
- 库存总表实时人民币等值包含其本币库存。
- 允许：付款、核销、补费用（前向调整）、汇率换算、成本分析、利润分析。
- 禁止：修改已锁定快照（只允许前向调整/受控重确认）、重新打开为 OPEN、影响其他 CI 成本。
- 关闭态（CLOSED 但库存>0）同样适用本类行为。

### 25.3 B 类：历史 CI 库存 = 0（只参与财务与历史分析）

- 行为：运营 WAC **不再含其份额**；任何后续动作**只进财务维度与历史利润分析**。
- **硬禁止影响**：当前库存、当前 WAC、订单预测、补货/采购建议。
- 允许：付款、核销、补费用（仅历史成本分析，不影响运营，见 §24.3）、汇率换算、成本分析、利润分析。
- 与 §18 硬约束一致，此处明确状态划分：B 类是完全脱离运营、仅留财务与历史的 CI。

### 25.4 两类转换

- 当 A 类 CI 库存随出库降为 0，自动转为 B 类（或经 §23.4 关闭后明确为 B 类）。
- 转换不改变已锁定快照与历史利润，仅改变其后续补费用是否影响运营 WAC（B 类不影响）。
