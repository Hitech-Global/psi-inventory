## 一、抽样验收（字段逻辑一致性）

对 6 类 SKU 各抽 2 条对账，结论：**所有抽样行的字段间关系逻辑自洽**。

| 检查项 | 公式（代码依据） | 抽样结果 |
|---|---|---|
| 线上/线下/总 90天月均 | `online_avg_sales_period` / `offline_avg_sales_period` / `avg_sales_period` | 三者满足 线上+线下≈总（渠道求和）✓ |
| 线上占比 / 线下占比 | `round(线上period月均 / 总period月均 ×100)` | 抽样均 100%/0% 或 88%/12% 等，和≈100% ✓ |
| 当前可用周转(总预测) | `round(可用库存 / 总period月均 ×10)/10` | 与 可用库存÷月均 一致 ✓ |
| 在途后周转(总预测) | `round((可用+在途) / 总period月均 ×10)/10` | 一致 ✓ |
| 下单后周转(总预测) | `round((可用+在途+建议采购) / 总period月均 ×10)/10` | 一致 ✓ |
| 目标库存 | `round(渠道period月均 × 渠道目标周转)` | 线上目标库存=`round(线上月均×线上周转)`、线下同理，全部吻合 ✓ |
| 总库存池 | `可用+在途+PI已确认未发货+PO未确认PI` | 与存储 `total_inventory_pool` 逐项一致（0 处不符）✓ |

**代表性样本：**
- **双渠道 / 建议采购较大** `BYMINIDB`（BOYA）：线上月均 24.67、线下 3.33、总 28；线上目标库存 74+线下 10=84，当前池仅 2 → 建议采购 **82**（缺口大，合理）。
- **建议采购=0（拦截）** `BOYAMIC`（BOYA）：风险标签含「高库存严重/高库存关注/高库龄风险」+ 动销=新品/销售数据不足 → `shouldBlockReplenish` 返回 true → 建议采购 **0**（合理）。
- **纯线上** `BOYAMIC` 线下月均=0 → 线下占比 0%、线下目标库存 0（合理）。

## 二、建议采购逻辑验收

- **是否已按销量统计周期口径？** 是。建议采购的基数来自 `avg_sales_period` / `online_avg_sales_period`（`=近90天有效销量÷90×30`），非 4 个月口径；目标周转取自 `dim_default_config` 命中值。✓
- **命中的目标周转规则**（每行的 `online_target_turnover/offset` 与 `getDimTurnover` 评分一致）：
  - Redragon 全部 103 行 → 命中 `{Redragon,∅,∅}` 周转 **4** ✓
  - Netac 全部 198 行 → 命中 `{Netac,∅,∅}` 周转 **2** ✓
  - Redragon/印度尼西亚/Bekasi → 命中专属规则 4 ✓
- **为何建议采购=0**：两类——① 业务拦截（`shouldBlockReplenish`：清仓/停采/无有效销售/呆滞/慢销/高库存严重/高库存关注/高库龄风险/新品无销量）；② `目标库存 ≤ 已分摊库存`（库存已够）。抽样均符合。
- **为何建议采购较大**：`目标库存 − 库存池分摊` 缺口大。如 `BYMINIDB` 目标 84、池 2 → 82。符合公式。

## 三、建议动作 / 建议描述验收

- 建议动作（页面 `建议动作` 列取自 `r.action`；`建议动作(suggestion)` 列另由 `lifecycle_status` 派生）与数据基本自洽：`缺货/缺货风险`→优先补货类、`慢销/呆滞`→暂缓、`清仓`→不补，均对应。
- **一处需注意（非逻辑错误，属设计/数据叠加）**：`lifecycle_status=new_test` 的 SKU，`suggestion` 恒为「新品导入，不直接生成PO」，即使其 `建议采购>0`（如 `BYMINIDB` 建议采购=82 仍显示此文案）。这是生命周期规则（新品只手动建 PO）的预期结果，但「建议采购有正数」与「不直接生成PO」并排可能让使用者略困惑。可在后续优化文案（如改为「新品导入，建议备货 82（手动建PO）」）。这些行同时也属于下方「陈旧数据」集合。

## 五、最终验收结论

### 1. 已通过的逻辑（核心计算正确）
- 目标库存 = 渠道 period 月均 × 命中目标周转（Redragon 4 / Netac 2 全部精确吻合）。
- 总库存池 = 可用+在途+PI已确认未发货+PO未确认PI（0 处不符）。
- 建议采购 = 业务拦截后 `目标库存 − 渠道分摊库存` 缺口，拦截规则与动销状态/风险标签一致。
- 三周转指标（当前可用/在途后/下单后）前端公式与「可用/可用+在途/可用+在途+建议采购 ÷ period月均」自洽。
- 占比（线上+线下≈100%）、分摊口径一致。
- 顶部 5 项汇总指标与明细重算逐项精确一致。
- 建议采购已按**销量统计周期(90天)**口径计算，目标周转取自当前 `dim_default_config` 命中。

### 2. 发现的问题（均非代码计算 bug，按你要求只列不改）

**【问题 A｜重要】75/376 行是"陈旧数据"，当前配置下已"未命中规则"**
- 分布：BOYA×66、Joypeer×4、TestBrand×3、测试品牌×2。
- 原因：这些行是在**旧"默认周转=3"兜底**尚存时生成的；你确认"去兜底"后，当前 `dim_default_config` 已无默认行，这 4 个品牌无任何命中规则。
- 表现：这些行现在显示的 周转(3)/目标库存/建议采购 均基于已失效的默认 3；**若现在点"重新计算"，会被后端预检拦截（弹"未命中规则"提示），不会偷偷用旧值**。
- 影响：页面当前给这 75 行展示的是陈旧且不再被系统认可的数值。
- 建议（待你决定，本轮未执行）：在「预测参数设置」为 BOYA / Joypeer / TestBrand / 测试品牌 各补一条品牌级规则（或一条全通配兜底），再点"重新计算"刷新这 75 行。这恰好是上一轮"去兜底"决策的**预期后续动作**。

**【问题 B｜轻微】下单后周转存在 ≤0.1 月的舍入差（22 行）**
- 原因：DB 存储的 `after_order_turnover_months` 用生成时的**原始精度** `avg_sales_period` 计算；而页面前端显示用**入库时已四舍五入到 2 位**的 `avg_sales_period` 重算。二者差 ≤0.1 月。
- 影响：页面实际显示的是前端重算值（与同屏其它字段一致），DB 存储值未被直接展示，**用户不可见不一致**。属无害的舍入特征。

**【问题 C｜轻微】1 行建议采购差 1（BYOMICDW：存 10 / 重算 11）**
- 落在 BOYA 陈旧数据集内，由"陈旧目标库存 + 分摊四舍五入边界"导致，量级 1，对决策无实质影响。

**【问题 D｜文案】new_test 生命周期的"建议动作"文案与"建议采购>0"并存**
- 见第三节。设计如此（新品仅手动建 PO），但建议优化文案以消除并列困惑。属体验优化，非逻辑错误。

### 3. 是否还有明显不合理 / 自相矛盾
- **计算逻辑层面：无自相矛盾**，核心公式、拦截、汇总均自洽。
- **数据状态层面：有问题 A（75 行陈旧）**，这是"去兜底"决策的预期遗留，需在补规则+重算后消除；问题 B/C/D 均为无害级。
- 本轮未改动任何代码，仅做了只读对账。
