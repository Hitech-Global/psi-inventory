# P1-WAC-03-R1 汇率锚点业务口径纠正说明

> 本文档为 P1-WAC-03《汇率锚点与 rate_type 冻结稿》的**业务口径纠正说明**。
> **不修改原 P1-WAC-03 文件**，不修改代码、数据库、接口、页面、测试数据、日志、MEMORY.md，不输出 DDL，不进入 P1-WAC-04 或正式实施。
> 自本说明发布之日起，**P1-WAC-03 中"九类成本统一使用同一批次成本结算日汇率"的结论正式撤销**，以本说明口径为准。

---

## 1. 撤销原"统一成本结算日汇率"结论

原 P1-WAC-03 §一、§二、§四将以下结论作为冻结口径：

> "所有实际进入本批 WAC 的成本（CI 货款、国际运费、本地运费、关税、清关费、港杂费、派送费、商检费、其他本地费用）均统一按照同一批次已确认并锁定的**成本结算日**汇率换算为目标国家本国货币。"

**本说明正式撤销上述结论。** 理由：

- CI 货物成本的汇率锚点应为 **CI 出货日期**，而非 Cost Confirm 日期；
- 各项费用（运费、关税、清关费等）的汇率锚点应为**该笔费用各自的实际付款完成日期**，彼此可不同；
- 强制统一为单一"成本结算日"会错配货物成本与费用的真实结算时点，违背《成本与汇率计算规则 Final V1.0》"不得把付款日、成本确认日、运费付款日、CI 日期合并为同一个日期"的禁止性规定。

撤销后，P1-WAC-03 中与"统一成本结算日"直接相关的表述（§一"WAC 成本层统一使用成本结算日"、§二"统一按成本结算日"、§四"成本结算日默认 Cost Confirm 当天"作为 WAC 汇率锚点）**不再作为有效冻结口径**，改以本说明第二、三、四节为准。

> 注：原 R1（P1-WAC-01-R1）"本地费用使用各自冻结的付款日期汇率"与本说明方向一致，但原 R1 未单独界定 CI 货物成本应使用 CI 出货日期（R1 当时沿用 P1-WAC-03 的"成本结算日"假设）。本说明补齐该区分后，三份文件（P1-WAC-01-R1 / P1-WAC-03 / 本 R1）关于"费用按各自付款日"一致；关于"CI 货物成本按 CI 出货日"以本说明为准。

## 2. CI 货物成本使用 CI 出货日期

### 2.1 规则

1. 正式货物成本来源 = **CI 货款金额**（`commercial_invoices.goods_amount`，原币 `commercial_invoices.currency`）。
2. 账单原币金额**固定**，不参与重算。
3. 汇率日期 = **CI 出货日期**。
4. **不使用** Cost Confirm 日期、**不使用**定金付款日期、**不使用**尾款付款日期。
5. 换算链路：
   `CI 原币金额 → CI 出货日期汇率 → 库存国家本国货币金额`。
6. 换算结果确认后**锁定汇率事实**；后续汇率更新不得改变已确认货物成本或历史 WAC。

### 2.2 定金 / 尾款只是付款拆分，不进入成本

- `commercial_invoices.should_deduct_deposit` / `actual_deducted_deposit` 证实定金、尾款为货款的**付款拆分**，仅影响现金收付与余额（`payable_balance`/`paid_balance`/`unpaid_balance`），**不改变货物成本金额**。
- 定金、尾款**不得重复进入 WAC**（原 P1-WAC-01 已发现"抵扣/定金/尾款当前根本未进入成本分摊"，本说明进一步确认：即便未来纳入付款层，也只作为付款事实，不作为第二次货物成本）。

### 2.3 数据现状与待定义项（只读发现，本轮不修改）

- `commercial_invoices` **当前没有** `shipment_date` / `ship_date` 字段（仅有 `ci_date`、`created_at`、`updated_at`、`wac_confirmed_at`）。
- 候选来源：`logistics_batches` 含 `depart_date`（发货）、`eta_date`（到港）、`actual_arrival_date`、`inbound_complete_date`；CI 与物流批次通过 `related_ci_id` 关联。
- **待定义（留给 P1-WAC-04 / 实施设计）**：CI 出货日期的权威字段定义（建议取 `logistics_batches.depart_date` 或新增 `commercial_invoices.shipment_date`），以及当一 CI 对应多物流批次时取哪个日期。本轮仅冻结"锚点=CI 出货日期"这一业务语义，不决定具体字段。

## 3. 各项费用使用各自实际付款完成日期

### 3.1 适用费用

以下费用**不使用 CI 出货日期**，也**不与 CI 货物成本共用同一汇率日期**：

- 国际运费
- 本地运费
- 关税
- 清关费
- 港杂费
- 派送费
- 商检费
- 其他实际进入落地成本的费用

### 3.2 规则

- 每笔费用原币金额 → **该笔费用实际付款完成日**汇率 → 库存国家本国货币金额。
- 不同费用即使属于同一张 CI，也可能具有不同：
  - 付款日期；
  - 汇率日期；
  - 汇率数值；
  - 汇率快照。
- **不得强制共用** CI 出货日期、Cost Confirm 日期或其他统一日期。

### 3.3 费用来源与付款日现状（只读发现，本轮不修改）

- `ci_cost_items`：有 `payable_amount`、`paid_amount`、`currency`、`payment_request_id`、`include_in_landing_cost`，**无付款日期字段**。
- `logistics_batches`：有 `international_freight`/`local_charges`/`customs_duty`/`vat_gst`/`other_fees` 等金额与 `freight_currency`，及多个物流节点日期（`depart_date`/`eta_date`/`actual_arrival_date`/`customs_start/end_date`/`delivery_date`/`inbound_complete_date`），**无"运费付款完成日"字段**。
- 实际付款完成日权威来源在付款层：`payment_transactions.paid_date`（经 `payment_request_id` → `payment_requests` 关联）。
- **待定义（留给 P1-WAC-04 / 实施设计）**：费用"实际付款完成日"如何从左述付款层可靠取得（尤其一笔费用对应多笔付款时的取数规则，见第八节）。本轮仅冻结"锚点=该费用实际付款完成日"这一业务语义。

### 3.4 各费用锚点一览（业务语义冻结，不含数据库字段）

| 成本类型 | 原币来源 | 目标本币 | 汇率锚点 |
|---|---|---|---|
| CI 货物成本 | `commercial_invoices.goods_amount` + `currency` | 库存国本币 | **CI 出货日期** |
| 国际运费 | `logistics_batches.international_freight` + `freight_currency` | 库存国本币 | 该运费实际付款完成日 |
| 本地运费 | `logistics_batches.local_charges` 或 `ci_cost_items`(本地运费) | 库存国本币 | 该费用实际付款完成日 |
| 关税 | `logistics_batches.customs_duty` / `ci_cost_items`(customs_duty) | 库存国本币 | 该费用实际付款完成日 |
| 清关费 | `logistics_batches.customs_service_fee` / `ci_cost_items` | 库存国本币 | 该费用实际付款完成日 |
| 港杂费 | `ci_cost_items`(港口杂费) | 库存国本币 | 该费用实际付款完成日 |
| 派送费 | `logistics_batches.delivery_fee` / `ci_cost_items` | 库存国本币 | 该费用实际付款完成日 |
| 商检费 | `ci_cost_items`(inspection_fee) | 库存国本币 | 该费用实际付款完成日 |
| 其他本地费用 | `logistics_batches.other_fees` / `ci_cost_items`(其他) | 库存国本币 | 该费用实际付款完成日 |

> `rate_type` 仍按 P1-WAC-03 三层分离：WAC 成本换算使用 `cost_settlement`（货物与费用虽锚点日期不同，但均属 WAC 成本层，统一记为成本结算汇率类型，区别于 `realtime` 与 `payment`）；付款日快照（如有并行财务层）记 `payment`。本说明不重新定义 rate_type 枚举，沿用 P1-WAC-03 §三语义。

## 4. Cost Confirm 日期仅为确认锁定日期

- Cost Confirm 日期 = `commercial_invoices.wac_confirmed_at`（现状字段）。
- 语义：**成本确认操作日期**，用于确认、锁定与审计。
- **不是**货物成本或各项费用的默认汇率日期。
- 不得把以下三个日期合并为同一字段或同一业务概念：

| 日期 | 角色 | 用作汇率锚点？ |
|---|---|---|
| CI 出货日期 | CI 货物成本汇率锚点 | ✅ 仅货物成本 |
| 各项费用实际付款完成日期 | 对应运费/关税/其他费用汇率锚点 | ✅ 仅对应费用 |
| Cost Confirm 日期 | 确认 / 锁定 / 审计 | ❌ 否 |

## 5. 同币种 rate=1 的审计规则

当费用原币已等于库存国家本国货币时（如印尼关税以 IDR 支付、马来本地费以 MYR、泰派送费以 THB）：

1. `exchange_rate = 1`；
2. 原币金额 = 本币金额；
3. **仍需保留可审计的同币种换算事实**，不得因为汇率为 1 而完全不记录币种和锚点信息；
4. 必须记录：
   - `source_currency` = `target_currency`（如 IDR→IDR）；
   - `rate_date` = 该费用实际付款完成日（或 CI 出货日，依成本类型）；
   - `rate_type` = `cost_settlement`；
   - `exchange_rate = 1`；
   - `rate_source`（如"同币种免换算"标记）；
   - 原始方向与使用方向一致；
   - 仍生成**独立的不可变汇率快照**（见第六节），与其他成本来源的快照同等参与追溯。

---

## 6. 各成本来源独立汇率快照要求

1. **每个成本来源独立生成一份汇率快照**：
   - CI 货物成本 → 1 份（锚点 CI 出货日）；
   - 每笔费用 → 各 1 份（锚点该费用实际付款完成日）；
   - 即使同 CI、同币种、同数值，只要锚点日期或 rate_type 不同，即为不同快照。
2. **一条 `wac_history` 关联多笔成本来源**，每笔成本来源关联其各自汇率快照（具体关联结构由 P1-WAC-04 设计，禁止在 `wac_history` 单字段内以 JSON / 逗号拼接 / 无外键数组保存多个快照 ID）。
3. 快照**不可变**：已引用快照不得被后续汇率同步覆盖或删除。
4. 快照**事实指纹**复用判断（承 P1-WAC-03 §四修正）：仅当 source/target/rate_date/rate_type/exchange_rate/rate_source/方向/是否倒数/是否交叉/桥接币种/组成快照/精度/舍入/人工确认等**完整指纹一致**时才允许复用既有不可变快照；任一事实不同须生成新快照。
5. 缺汇率时**阻断**（承 P1-WAC-03 §五）：优先查 cost_settlement + 对应锚点日期；缺失不得静默用 realtime / 最新汇率 / 默认币种；目标国未配置本币则阻断提示"当前国家未纳入 WAC 业务范围"。

## 7. 对 P1-WAC-04 快照模型的影响

本说明改变了 P1-WAC-04 的设计前提，须在原 P1-WAC-04 任务范围（"汇率快照与成本换算证据模型设计"）中落实以下调整：

1. **快照不是批次级，而是成本源级，且锚点异构**：
   - 同一 `wac_history` 下可能并存"CI 出货日锚点"的货物成本快照与多个"费用付款完成日锚点"的费用快照；
   - 快照模型必须支持**同一 WAC 版本内多锚点日期、多 rate 值**共存，而非单一 settlement_date 派生全部。
2. **成本换算证据（cost conversion evidence）须绑定到具体成本来源**，记录该来源的：原币、锚点日期类型（CI 出货日 / 费用付款日）、锚点日期值、rate_type、所用快照 ID。
3. **`wac_history.settlement_date`（现状字段）语义需重新界定**：它当前是 Cost Confirm 当天（`datetime('now')`），不再是 WAC 汇率锚点；P1-WAC-04 应将其定位为"确认操作日期"或废弃，汇率锚点改由各成本源证据携带。
4. **同币种 rate=1 快照**须作为一类显式快照被模型容纳（§5）。
5. **追溯链**：`wac_history →（关联）成本来源行 →（各自）汇率快照`，满足"从最终 wac_history 追溯到每个成本来源及其汇率事实"。
6. **避免重复快照**：同一费用分摊到多 SKU/仓库时，汇率快照在"成本来源"层生成一次，分摊行共享引用，不在每行新建（承 P1-WAC-04 §7.11 / P1-WAC-02 冻结）。
7. **数据缺口需在 P1-WAC-04 一并给出字段方案**：CI 出货日期字段、费用付款完成日字段（见第二、三节待定义项）——P1-WAC-04 可输出候选表/字段，但本轮不执行 DDL。

## 8. 分次支付同一费用时仍需后续裁断的问题

**本说明不予裁定，列为待用户裁断项**，不擅自决定：

- 场景：一笔费用（如国际运费）分多次付款（定金 + 尾款 / 多笔 `payment_transactions`）。
- 开放问题：
  1. 汇率锚点取**首次付款完成日**、**末次付款完成日**、还是**按金额加权**？
  2. 若多次付款跨不同汇率日期，是否需按付款比例拆分成多份成本源快照？
  3. 若仅部分付款即做成本确认，未付部分是否允许暂估、后续补快照？
- 处理原则：本轮仅冻结"锚点=该费用实际付款完成日"这一语义；**具体取数规则留给 P1-WAC-05（直接/倒数/交叉汇率规则）或专项裁断**，不在此预置复杂模型，亦不静默采用任一默认。
