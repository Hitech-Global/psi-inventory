## 二、当前筛选条件如何显示在弹窗里

打开弹窗时（`openRpParams` 启动），先 `currentRpContext()` 取 `rp-c/rp-w/rp-b` 实值，渲染为**只读上下文横幅**：

```
当前正在配置目标周转规则：
[品牌: Redragon]  [国家: 印尼]  [仓库: 通配（全部）]
```

- 非空白 → 显示实际值（蓝/绿徽章）。
- 空白（=全部）→ 显示「通配（全部）」（灰徽章），旁注「通配=该维度不限，命中时作更宽范围兜底」。

横幅下方紧跟**只读参考块「当前维度实际命中到的已有规则」**：

- 调 `resolveDimHit(rules, brand, country, warehouse)`，有命中则显示：
  `命中：品牌=Redragon / 国家=通配 / 仓库=通配 → 线上 4 / 线下 4（优先级得分 4）`
- 无命中显示：`当前维度暂无命中规则（保存后将新增此维度规则）`

> 这块只读显示让你保存前就能看清「现在到底按哪条规则算、将要改成什么」，防止误覆盖。

## 三、保存时「当前上下文 upsert」到底怎么做

`saveRpParams()` 算法（伪代码）：

```js
const ctx = currentRpContext();            // {brand, country, warehouse}（空=通配）
const online  = parseFloat(线上输入框) || 0;
const offline = parseFloat(线下输入框) || 0;
if (!(online>0) || !(offline>0)) { toast('周转值必须为正数'); return; }

// 全通配（三处皆空）→ 强二次确认
if (!ctx.brand && !ctx.country && !ctx.warehouse) {
  if (!confirm('你正在配置「全通配」规则，将作为所有未单独配置 SKU 的最低优先级兜底。确认需要吗？')) return;
}

const newRule = {
  brand: ctx.brand, country: ctx.country, warehouse: ctx.warehouse,
  online_turnover: online, offline_turnover: offline
};
const key = (r)=> (r.brand||'')+'|'+(r.country||'')+'|'+(r.warehouse||'');

// 1) 现有规则（openRpParams 暂存的 _rpLoadedDimRules）
let rules = (_rpLoadedDimRules || []).slice();
// 2) 删同键旧规则
rules = rules.filter(r => key(r) !== key(newRule));
// 3) 追加当前上下文新规则（upsert 完成）
rules.push(newRule);
// 4) 合并高级区手动添加的行（若有），按 key 去重，当前上下文优先
collectAdvancedRows().forEach(ar => {
  if (!rules.some(r => key(r) === key(ar))) rules.push(ar);
});

// 5) 整体保存（沿用现有通用接口，后端零改动）
POST /api/system-config { configs: [
  {key:'sales_stats_days', value: sd},
  {key:'dim_default_config', value: JSON.stringify(rules)}
]};
```

要点：
- **只动当前上下文这一条**：同键旧规则被删、新规则追加，其余规则原样保留。
- 后端接口、字段结构、`getDimTurnover` 评分命中逻辑**完全不变**——前端只是把「合并后的完整数组」交回去。
- 保存后仍提示「请点击重新计算使新参数生效」，并刷新 `rpSalesStatsDays` 缓存（与现行为一致）。

## 四、旧的自由规则表：折叠到「高级设置」，不直接铺开

- 默认界面**只显示**：上下文横幅 + 线上周转 + 线下周转 + 命中规则只读参考。
- 旧的 brand/country/warehouse/online/offline 自由表 + 「+ 新增规则」按钮 → 收进 **「⚙ 高级设置（折叠）」**，默认 `display:none`/折叠。
- 高级区保留 `addRpDimRow()` 原逻辑，供需要配置「当前未筛选到的维度」时应急。
- 高级区填写的行，保存时随 upsert 一起合并（按 key 去重，当前上下文优先）。
- 主路径不再依赖自由表，符合「不让我维护抽象自由表」。

## 五、三种筛选场景 → 分别保存成什么规则

设线上周转填 `A`、线下周转填 `B`（A、B 为输入框正数）。

| 场景 | 筛选 | 存入 dim_default_config 的规则 | 命中含义 |
|---|---|---|---|
| A | 品牌=Redragon，国家=印尼，仓库=全部 | `{brand:"Redragon", country:"印尼", warehouse:"", online:A, offline:B}` | 品牌+国家规则（得分6）。Redragon 在印尼、任意仓库的 SKU 都命中它。 |
| B | 品牌=全部，国家=印尼，仓库=Bekasi | `{brand:"", country:"印尼", warehouse:"Bekasi", online:A, offline:B}` | 国家+仓库规则（得分3）。**印尼 + Bekasi 下的所有品牌**都命中（跨品牌）。弹窗提示「将作用于该国家/仓库下全部品牌」。 |
| C | 三个都是全部 | `{brand:"", country:"", warehouse:"", online:A, offline:B}` | 全通配（得分0）。所有未被更具体规则命中的 SKU 都兜底命中它。**需二次确认**，避免误成全局默认。 |

- 场景 C 不会覆盖已有更具体规则：`getDimTurnover` 评分永远优先选最高分（Redragon/Netac 等专属规则仍胜出），全通配只在「无任何更具体命中」时生效。
- 场景 A/B/C 保存时均执行 upsert：若同键已存在则覆盖，不存在则新增，其它维度规则不受影响。

## 七、验证清单（实施后用，不改生产理解）

1. 筛选 Redragon/印尼/全部 → 打开弹窗：横幅显示正确；线上/线下预填为该上下文已配值（若已配）或参考值。
2. 改值保存 → DB 的 `dim_default_config` 中 Redragon/印尼/通配 变为新值；Redragon/通配/通配、Netac 等其它规则原样保留（不被误删）。
3. 场景 B（品牌=全部）保存 → 弹窗出现跨品牌提示；保存后印尼+Bekasi 下多品牌命中该规则。
4. 场景 C（三全全部）保存 → 弹二次确认；确认后写入全通配；Redragon/Netac 专属规则仍优先（generate 不被全通配覆盖）。
5. 高级设置折叠区：默认隐藏；展开后可加其它维度行，保存合并生效。
6. 当前维度命中只读块：与 `getDimTurnover` 后端结果一致（前端镜像评分验证）。
7. 重新计算（当前筛选）→ 命中成功，不再被未命中拦截。
