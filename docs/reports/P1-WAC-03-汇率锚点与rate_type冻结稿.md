### 1.2 当前汇率表（关键事实）

`exchange_rates` 列：`id, from_currency, to_currency, rate, rate_date, rate_type, created_at`。
- 全表仅 **1 行**：`IDR → RMB, rate=0.000377, rate_date=2026-07-05, rate_type='realtime'`。
- **问题**：① 仅有 IDR→RMB，缺少 WAC 必需的 `USD→IDR / USD→MYR / USD→THB / RMB→MYR / RMB→THB` 等；② 仅有 `rate_type='realtime'`（实时展示汇率，Final V1.0 §2.B），**没有成本结算口径与付款口径的独立 rate_type 记录**。
- 该表在成本确认 / 库存刷新链路中**当前完全未被读取**（Final V1.0 §25.1 要求系统唯一来源，但代码未消费）。

### 1.3 当前"日期/汇率"在 WAC 链路中的真实消费情况

- `wac_history` 已存在列：`settlement_date, confirmation_status, confirmed_by, confirmed_at`（26 列之一）。
  - 当前 `settlement_date` 由代码以 `datetime('now')` 写入（即"今天"），**并非** Final V1.0 §27 的"成本结算日（默认 Cost Confirm 当天，受控例外可选业务日期）"语义；且**未用于任何折算**。
- `cost_allocations` 当前字段：`product_cost / allocated_freight / allocated_duty / allocated_other / total_landing_cost / unit_landing_cost / currency / unit_landing_cost_with_fees / original_qty / original_avg_cost`。
  - **无 rate_type、无 settlement_date、无汇率、无快照引用**。
- 当前 WAC 公式（`server.js` 约 4844–4847，源自 P1-WAC-01 排查）：把 `inventory.weighted_avg_cost`（**本币**）与 `cost_allocations.unit_landing_cost`（**CI 原币/混合原币**）直接相加平均，**不读取 exchange_rates、不读取任何日期、不做换算、无货币标注**。
- 结论：**当前没有任何成本在 WAC 折算时读取"汇率日期"或"rate_type"；所有成本均处于"零汇率锚点"状态**。

## 2. 当前问题

1. **零汇率锚点**：所有进入 WAC 的成本在折算时既不读 `exchange_rates`、也不读任何日期，原币与本币直接混算（P1-WAC-01 已确认缺陷）。
2. **无 rate_type 区分**：`exchange_rates` 仅有 `realtime`，WAC 与付款口径没有独立 rate_type；违反 Final V1.0 §25.2「唯一生效键必须含 rate_type」。
3. **结算日语义错位**：`wac_history.settlement_date` 写的是"今天"，不等于 Final V1.0 §27 的"成本结算日"语义，且未参与折算。
4. **汇率数据缺失**：缺少 `USD→IDR/MYR/THB` 及 `RMB→MYR/THB` 的成本结算口径记录。
5. **费用币种数据缺陷**：样例 `ci_cost_items` 的关税/商检/到仓费全为 USD，与"本地费用应为本币"冲突（P1-WAC-02 已指出）。
6. **付款日快照缺失**：§15.A 要求的每笔费用付款日快照（财务层）未实现，`payment_requests.payable_date` 未被消费。
7. **R1 表述与 Final V1.0 冲突**（重要，见 §4 与 §8）：R1 曾写"本地费用使用各自冻结的付款日期汇率"，但 Final V1.0 §15.B/§15.C.5/§17 明确"批次 WAC 成本口径统一按成本结算日折算，付款日折算金额不得替代批次 WAC 成本金额"。本轮以 Final V1.0 为权威基线，结论为：WAC 批次层统一用**成本结算日 + 成本结算 rate_type**；付款日快照是**并行财务层**记录，不进入 WAC 初始成本。

## 3. 每种成本建议锚点（WAC 批次层）

> 下列"建议锚点"均为 **WAC 批次层（Final V1.0 §15.B）** 口径。依 Final V1.0 §15.B/§29，纳入成本的外币金额**统一按成本结算日汇率折算为本币**；§15.C.5 明确"不能使用付款日折算金额替代批次 WAC 成本金额"。
> 若某成本本身已为本国货币（LC），则"本币成本金额 = 原币金额，免换算"（§15.B 末 / §29.3）。

**统一结论**：WAC 批次层，九类成本**全部以"成本结算日 + 成本结算汇率 rate_type"为唯一折算锚点**，不按各费用付款日分别折算。这与 Final V1.0 §15.B「统一按成本结算日汇率折算成本币」完全一致。

**并行财务层（§15.A，不进入 WAC）**：每一笔费用另按自身**实际付款完成日**（取 `payment_requests.payable_date` / `payment_transactions.paid_date`）保存付款日快照，rate_type = **付款汇率**，用于财务付款、现金流、费用趋势。此快照与 WAC 批次层快照相互独立、可并存（§15.C.3）。

## 4. 每种成本建议 rate_type（冻结原则）

依据 Final V1.0 §2（两类汇率）/ §25.2（唯一生效键含 rate_type），rate_type 至少需区分：

- **`realtime`**：实时展示汇率（库存总表人民币等值，§2.B）。**不得**用于 WAC 折算（§2 / §19 严禁用实时汇率回填空缺成本结算快照）。当前 `exchange_rates` 唯一存在的即此类型。
- **成本结算汇率**（建议取值名待 P1-WAC-04/05 最终命名，如 `cost_settlement`）：WAC 批次层统一使用。Final V1.0 §15.B 的成本结算日快照即此类型。
- **付款汇率**（建议取值名待定，如 `payment`）：§15.A 每笔费用付款日快照使用。

**冻结原则（本轮）**：
1. WAC 折算汇率的 rate_type **必须独立于 `realtime`**，使用专属"成本结算汇率"类型。
2. 付款日快照的 rate_type **必须独立于 `realtime` 与"成本结算汇率"**，使用专属"付款汇率"类型。
3. 三类 rate_type 取值名的具体字符串、是否需再细分（如"历史 CI 衔接"），留待 P1-WAC-04/05 设计，本轮不预决。
4. 任何被业务采用的汇率**必须保存为快照**（§12.9），且快照记录其 rate_type。

## 5. 汇率快照复用原则

1. **唯一生效键**（Final V1.0 §25.2）：`from_currency + to_currency + rate_date + rate_type` 四元组唯一确定一条正式生效汇率。
2. **完全相同事实允许复用**：当某笔成本的 `(原币, 本币, 成本结算日, 成本结算汇率)` 与已存在快照四元组一致时，**复用同一条快照记录**（去重，不新建重复快照）；同一 CI 内多笔同币种成本（如 USD→IDR 货款 + USD→IDR 运费）在同日同 type 下**共享同一条成本结算快照**。
3. **不同币种对必须不同快照**：USD→IDR 与 RMB→IDR 即便同日同 type，亦为两条不同快照（from_currency 不同）。
4. **WAC 批次层快照与付款层快照分离**：成本结算快照（WAC 用）与付款日快照（财务用）即使日期相同也因 rate_type 不同而成两条独立快照，互不覆盖（§25.4 / §26.2）。
5. **锁定不可覆盖**：已被业务单据引用的快照，后续 `exchange_rates` 同步更新**不得覆盖**（§25.4 / §26）。
6. **复用 ≠ 改写**：复用只是引用同一快照 ID，快照值本身永久不变。

## 6. 缺汇率阻断原则（Final V1.0 §19 / §22.4.5）

1. **WAC 批次层缺成本结算日汇率**：禁止自动确认成本。按 §19 兜底顺序：① 自动补取该日真实汇率 → ② 向前最近可用日近似（标记 `nearest-available`，保留真实汇率日期，不得伪造目标日数据）→ ③ 极端无可用汇率，转**人工确认**（手动指定汇率值 + 日期，标记 `manual`，记录操作人/原因）；均不得用 `realtime` 回填空缺（§19 首句严禁）。
2. **付款层缺付款日汇率**：按 §15.A 同样兜底；付款日快照缺失不阻断 WAC（因付款快照不进入 WAC 初始成本），但须标记状态供财务补录。
3. **目标国家未配置本币**（ID/MY/TH 之外，或 country_id 无法映射本币）：成本确认必须**阻断**并提示"当前国家未纳入 WAC 业务范围"（承接 P1-WAC-02），禁止静默回退 USD/RMB。
4. **阻断为默认，人工确认为受控例外**：人工确认须记录操作人、原因、指定值/日期，并标记类型，不得静默放行。

## 7. 必须讨论（设计理由，不实施）

1. **货款为何不能用确认日期**：Final V1.0 §27 定义"成本结算日"默认即 Cost Confirm 当天，但它是**受控确定的结算锚点**而非随意"今天"；若直接用 `datetime('now')` 且允许任意改，会破坏 §9「锁定后永久保存、不受后续汇率波动影响」。故货款锚点 = 成本结算日（默认确认日，受控例外可改且留痕），**不是任意确认时刻**。
2. **国际运费为何不能用 CI 日期**：CI 日期是账单确立日，早于成本结算流程；§15.B 明确批次 WAC 用成本结算日，§15.C.5 禁止用其他日期折算金额替代批次成本。运费若用 CI 日期会与货款、其他费用锚点不一致，破坏"统一结算口径"（§25.3 同批口径一致）。
3. **本地费用为啥使用付款事实（财务层）**：§15.A 规定每笔费用按自身**付款完成日**保存快照，用于财务/趋势；但**该快照不进入 WAC 初始成本**（§15.C.5/§17）。即"本地费用有付款日快照"是财务层事实，"WAC 折算用成本结算日"是成本层事实，二者并存不冲突。
4. **为何不同费用不能共用一个汇率（WAC 层）**：若不同费用原币不同（如货款 USD、某费 RMB），同一 `from_currency` 不同则四元组不同，必须不同快照；若原币相同且同日同 type 则可**复用**同一快照（见 §5.2），这不是"共用错误汇率"而是"合法去重复用"。
5. **何时可复用同一汇率快照**：四元组 `(from,to,date,type)` 完全一致时复用（§5.2）；WAC 层多笔同币种成本天然复用成本结算快照。
6. **rate_type 是否应成为唯一生效键之一**：**是**（Final V1.0 §25.2 已冻结）。缺 rate_type 会导致 `realtime` 与成本结算汇率混淆，直接违反 §2 两类汇率分离。
7. **缺汇率时**：阻断优先（§22.4.5）；仅当走 §19 兜底（补取/近似标记/人工确认）且明确标记后才可继续，不得静默用实时汇率或默认币种。

## 8. 必须回答（逐项）

1. **同日两条 USD→IDR 但 rate_type 不同，是否同一汇率？** 否。唯一生效键含 rate_type（§25.2），不同 rate_type = 不同正式生效汇率，不得混用/覆盖。
2. **同日同币种不同来源，是否允许不同汇率？** 否。同一 `(from,to,date,type)` 只应有一条正式生效汇率（§25.2/§25.3）；"来源"不同不构成另立汇率的理由，业务只能引用该日正式生效汇率。
3. **汇率更新后历史 WAC 是否允许改变？** 否（§26）。已确认快照永久锁定，历史汇率更新 ≠ 历史成本重算；仅受控重确认可生成新版本（§30），不覆盖旧版。
4. **同一天重新确认，是否重新生成快照？** 重新确认属受控重确认（§20/§30），**生成新版本 + 新快照**；若四元组事实相同则新快照值与旧一致，但版本/记录为新，旧版保留不可删。
5. **取消确认后再次确认，是否生成新快照？** 是。取消（前向调整/受控）后再次 Cost Confirm 生成新 WAC 版本与新快照（§30.2），旧快照保留可追溯。
6. **完全相同汇率事实是否允许复用？** 允许且推荐（§5.2）。四元组一致即复用同一条快照记录，避免重复创建；复用是引用而非改写。

| 跨国家串仓 | 多国成本混算 | CI 跨国 | 单国家冻结（P1-WAC-02）+ 阻断（§6.3） |
