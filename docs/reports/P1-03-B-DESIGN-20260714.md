# P1-03-B 最小完整闭环实施设计稿

> 状态：**只读设计稿**，未实施、未改任何代码/数据库/接口/文档/测试数据。
> 冻结依据：SYS-E2E-02 正式结论基线 + 用户最终口径（2026-07-14 第 5 条修订）。
> 范围：**方案 B 最小完整闭环**，不含历史回填、不含完整 WAC 历史页面、不含汇率/负数入库/DELETE-first/重复付款/生产状态机等其它缺陷修复。

---

## 0. 设计原则（来自最终口径）

- **成本确认时（update-weighted-avg / 原 WAC 计算步骤）禁止写**：
  `inventory.available_qty`、`inventory.weighted_avg_cost`、`inventory.inventory_value`、`skus.weighted_avg_cost`。
- **成本确认时只允许写**：
  `wac_history`（新表）、`cost_allocations`（原字段回填）、`cost_update_logs`、`commercial_invoices` 成本确认状态、以及可选的 CI→WAC 版本引用。
- **WAC 历史表是唯一成本权威来源**；`inventory` 三字段是「ERP 当前库存导入」后的统一投影。
- **ERP 当前库存导入**是 `inventory` 三字段唯一合法的同步时点：同一事务更新 `available_qty + weighted_avg_cost + inventory_value`，且 `weighted_avg_cost` 取自最新已确认 WAC（不取文件值）。
- 三字段绝不允许只更新其中一个（无半更新状态）。

---

## 1. wac_history 最小表结构

按冻结需求 19 字段（成本版本号、CI 编号、PO 编号、SKU/Model、品牌、国家、仓库、入库前库存数量、原加权平均成本、原库存金额、本批实际入库数量、本批单位落地成本、本批总成本、新加权平均成本、成本结算日、确认状态、确认人、确认时间），落地为：

```sql
CREATE TABLE wac_history (
  id                TEXT PRIMARY KEY,            -- genId('wac')
  version_no        INTEGER NOT NULL,            -- 同 (sku_code,country,warehouse) 内自增
  sku_code          TEXT NOT NULL,
  model             TEXT,                         -- 取自 skus.model
  brand             TEXT,                         -- 取自 ci.brand / skus.brand
  country           TEXT NOT NULL,
  warehouse         TEXT NOT NULL,
  po_no             TEXT,                         -- ci.related_po_no
  pi_no             TEXT,                         -- ci.related_pi_no
  ci_no             TEXT NOT NULL,                -- ci.ci_no
  ci_id             TEXT,                         -- 便于关联
  pre_inbound_qty   REAL,                         -- 入库前库存数量（original_inventory_imports.original_qty）
  old_avg_cost      REAL,                         -- 原加权平均成本（上一条已确认版本或 inventory 旧值）
  old_inventory_amount REAL,                      -- 原库存金额 = pre_inbound_qty * old_avg_cost
  inbound_qty       REAL,                         -- 本批实际入库数量（cost_allocations.inbound_qty）
  unit_landing_cost REAL,                         -- 本批单位落地成本（cost_allocations.unit_landing_cost_with_fees）
  batch_total_cost  REAL,                         -- 本批总成本 = unit_landing_cost * inbound_qty
  new_avg_cost      REAL,                         -- 新加权平均成本（公式结果）
  settlement_date   TEXT,                         -- 成本结算日（默认 Cost Confirm 当天）
  confirmation_status TEXT NOT NULL DEFAULT 'confirmed',  -- 锁定后恒为 confirmed
  confirmed_by      TEXT,                         -- req.currentUserId
  confirmed_by_name TEXT,                         -- users.name
  confirmed_at      TEXT,                         -- datetime('now')
  remark            TEXT
);
```

> 注：`currency` 列暂不加入本表（避免与汇率换算缺陷 P1-WAC 耦合）；落地成本按当前系统既有口径（CI 原币）入表，汇率换算属另一独立 P1，本设计不修复。

## 2. 唯一键、版本号、索引与锁定规则

- **业务唯一键**：`UNIQUE (sku_code, country, warehouse, version_no)` —— 同一 SKU+国家+仓库 的版本号不重复。
- **版本号生成**：`version_no = (SELECT COALESCE(MAX(version_no),0)+1 FROM wac_history WHERE sku_code=? AND country=? AND warehouse=?) + 1`，在 `generateConfirmedWacVersions` 事务内计算，保证并发安全。
- **索引**：
  - `idx_wac_history_latest` ON `(sku_code, country, warehouse, version_no DESC)` —— 供「取最新已确认版本」高效查询。
  - `idx_wac_history_ci` ON `(ci_no)` —— 供 CI 维度回溯。
- **锁定规则**：
  - 一旦 `INSERT` 成功，该行成本字段（`old_avg_cost / new_avg_cost / qty / amount` 等）**不可 UPDATE**（实现上不提供任何 UPDATE 路径；如需纠错只新增一条更正版本，不覆盖）。
  - `confirmation_status` 恒为 `'confirmed'`，不提供 `pending/void` 状态流转（简化第一阶段）。
  - 不提供物理删除。

## 3. 新版本生成规则（generateConfirmedWacVersions）

输入：`ci_id`。前置（沿用现有 gate）：`cost_confirmed=1` 且 `cost_allocated=1` 且 `original_inventory_imported=1`。

伪代码（单事务）：

```
for each alloc in cost_allocations WHERE ci_id = ?:
    oi = original_inventory_imports 中 (ci_id, sku_code) 对应行  -- 取 country/warehouse/original_qty
    key = (alloc.sku_code, oi.country, oi.warehouse)
    old_avg_cost = latestConfirmedWac(key).new_avg_cost
                   ?? inventory.weighted_avg_cost (该 key 现有值) ?? 0   -- 首版回退
    pre_inbound_qty = oi.original_qty
    inbound_qty     = alloc.inbound_qty
    unit_landing    = alloc.unit_landing_cost_with_fees
    newAvg = (pre_inbound_qty*old_avg_cost + inbound_qty*unit_landing)
             / (pre_inbound_qty + inbound_qty)        -- 此公式沿用现有逻辑，仅不再写 inventory
    version_no = max(version_no for key) + 1
    INSERT wac_history (... all 19 fields ..., confirmation_status='confirmed',
                        confirmed_by, confirmed_by_name, confirmed_at=now,
                        settlement_date = date('now'))
    UPDATE cost_allocations SET original_qty=pre_inbound_qty, original_avg_cost=old_avg_cost WHERE id=alloc.id
    INSERT cost_update_logs (...)   -- 保留现有流水（只读兼容，不替代 wac_history）
```

要点：
- 每个 (sku, country, warehouse) 生成**一条独立锁定版本**。
- 不触碰 `inventory` / `skus` 任何列。
- 多次执行 = 追加新版本（version_no+1），不覆盖历史（满足「历史版本不得覆盖」）。

---

## 4. latest confirmed WAC 查询规则

统一函数（全系统唯一读取入口）：

```sql
SELECT new_avg_cost
FROM wac_history
WHERE sku_code = ? AND country = ? AND warehouse = ?
ORDER BY version_no DESC
LIMIT 1;
```

- 返回 `null` 表示「该 SKU+国家+仓库 尚无已确认 WAC」（触发第 9 节处理）。
- 所有读取方（ERP 导入、`inventory` 投影、成本页展示、订单预测成本口径）**必须**经此函数，不得再读 `inventory.weighted_avg_cost` 作为「最新已确认」来源（它仅是上一次 ERP 导入时的投影快照）。

## 5. 两套现有 WAC 函数收敛为一条权威路径

代码复核确认存在**两套并行 WAC 写入**：

| 路径 | 位置 | 当前写入 | 是否违规 |
|---|---|---|---|
| **A（并行）** | `allocateCosts`（路由 `POST /api/cost-allocation/allocate/:ci_id`，4650）→ 调用 `updateWeightedAvgCost(skuCode,…)` @ **4079** → 函数定义 **4083-4113** | `skus.weighted_avg_cost`、**`inventory.weighted_avg_cost` + `inventory.inventory_value`**（不写数量） | 违反「成本确认不写 inventory/skus」 |
| **B（违规量）** | 路由 `POST /api/cost-allocation/update-weighted-avg/:ci_id` @ **4711** | **`inventory.available_qty`** + `inventory.weighted_avg_cost` + `inventory.inventory_value` + `skus.weighted_avg_cost` + `cost_update_logs` | 违反 P1-03 核心 |

**收敛方案**：
1. **删除** `updateWeightedAvgCost` 函数定义（4083-4113）——它直接写 skus/inventory，是并行污染源。
2. **移除** `allocateCosts` 内第 4079 行调用 `updateWeightedAvgCost(skuCode, inboundQty, unitLandingCost);`，使 `allocate` 只产出 `cost_allocations`（中间结果），不再触碰成本/数量字段。
3. **重写** `update-weighted-avg` 路由（4711-4793）：不再写 `inventory`/`skus`，改为调用 `generateConfirmedWacVersions(ciId)`（第 3 节）。其现有前置校验（cost_confirmed / cost_allocated / original_imported / allocations 非空）全部保留。
4. 此后**唯一权威路径** = `generateConfirmedWacVersions` → 只写 `wac_history`（+ cost_allocations 原字段回填 + cost_update_logs + CI 引用）。

## 6. 成本确认事务边界

- 范围：仅 `generateConfirmedWacVersions` 内部。
- 包含写操作：`INSERT wac_history`（每条 SKU×国家×仓库）、`UPDATE cost_allocations(original_qty, original_avg_cost)`、`INSERT cost_update_logs`、`UPDATE commercial_invoices`（可选：写入 `latest_wac_version_id` 引用，非必需）。
- **明确排除**：任何对 `inventory`、`skus` 的 UPDATE/INSERT。
- 一致性：版本号在事务内取 MAX+1，事务回滚则全部版本不落库。
- 幂等：重复调用 = 追加新版本（不幂等覆盖），符合「每次确认生成并锁定新版本」。

## 7. ERP 当前库存导入事务边界

- 入口：`POST /api/inventory-imports/bulk-import`（1306）→ `refreshInventoryTotals(snapshotCutoffDate)`（1392）。
- 改写 `refreshInventoryTotals` 的 WAC 取值（第 1403 行）：
  - **删除** `const wac = parseFloat(imp.weighted_avg_cost) || 0;`（不再信任文件 WAC）。
  - **改为** `const wac = latestConfirmedWac(imp.sku_code, imp.country, imp.warehouse);`；若返回 `null` 按第 9 节处理。
- 同一事务内（1400-1418 已有 `transaction`）：
  - `UPDATE inventory SET available_qty = imp.available_qty, weighted_avg_cost = wac, inventory_value = imp.available_qty * wac, wac_pending = 0, … WHERE (sku,country,warehouse)` —— **三字段同一语句更新，杜绝半更新**。
  - 新增行同理在 INSERT 中一次性写入三字段。
- `updateInventoryTransitData()`（1420）保持不变（只更在途，不碰 available_qty）。

## 8. inventory 三字段同时更新规则

- 仅允许在 `refreshInventoryTotals` 内更新 `inventory.available_qty / weighted_avg_cost / inventory_value`。
- 三者**必须在同一条 SQL**（或同一事务且紧邻）完成；任何其它代码路径（出库、盘点、手动调整、作废）只改 `available_qty`，不得改 `weighted_avg_cost`/`inventory_value` 除以下情形：
  - 出库/盘点/调整改 `available_qty` 后如需同步金额，应一并按「当前 `weighted_avg_cost`（=最新已确认投影）× 新数量」重算 `inventory_value`（沿用既有逻辑，不引入新口径）。
- `inventory.weighted_avg_cost` 在两次 ERP 导入之间保持「上一次导入时的投影值」，不在成本确认时变更（满足第 4 节状态/显示规则）。

## 9. 无已确认 WAC 时 ERP 导入如何处理（推荐方案）

**推荐：允许数量导入，保留旧 WAC，标记成本待确认（`wac_pending = 1`）。**

理由：
- 阻止导入（方案二）会阻断「无 CI 的纯 ERP 补货 SKU」合法入库，影响面过大。
- 直接以文件 WAC 覆盖（原行为）违反冻结口径（文件 WAC 非权威来源）。
- 保留旧 WAC + 标记 `wac_pending=1`，既更新了真实数量，又明确告知「成本尚未匹配最新已确认版本」，等待后续 CI 成本确认 + 再一次导入时自然修正，无伪造审计事实。

实现：
- `inventory` 新增列 `wac_pending INTEGER DEFAULT 0`。
- `refreshInventoryTotals` 中：`wac` 为 `null` 时，`weighted_avg_cost` 保持 `inventory` 现有值（不写文件值），`wac_pending = 1`，`inventory_value = available_qty * 现有 weighted_avg_cost`。
- 成本页/库存总表可显示 `wac_pending` 标记（提示「成本待确认」）。

## 10. 导入文件中的 WAC 列兼容

- **DB 列 `inventory_imports.weighted_avg_cost` 保留**（向后兼容，避免破坏既有导入历史）。
- **官方成本不使用该列**（第 7 节已改为查 wac_history）。
- **模板处理**：从 `original-inventory/template` 与 ERP 导入模板中**移除/重命名** `weighted_avg_cost` 列为「文件WAC（仅供参考，不用于成本）」，避免用户误填并被误用。
- 前端导入页文案注明：「系统将按 SKU+国家+仓库 自动匹配最新已确认加权平均成本，文件中的成本列不生效」。

## 11. CI 与 WAC 版本的关联方式

- 主关联：`wac_history.ci_no` / `wac_history.ci_id`（每次生成时写入，天然按 CI 回溯所有版本）。
- 可选快速引用（非必需）：`commercial_invoices.latest_wac_version_id` —— 指向该 CI 最新版本的 `wac_history.id`，便于成本页一键展示；**不强制**，因为 `wac_history WHERE ci_no=?` 已可查全。
- 不在 CI 上存「已确认 WAC 数值快照」（避免与 wac_history 双源），CI 只存「是否已有确认版本」的派生标志（可由 `EXISTS wac_history WHERE ci_no` 动态判定）。

**代码回滚（server.js / app.js / db.js 改动 git revert 或逐段还原）**：
1. 还原 `update-weighted-avg` 路由（4711-4793）为原逻辑（恢复 inventory/skus 写入）。
2. 还原 `allocateCosts` 第 4079 行调用 `updateWeightedAvgCost`。
3. 还原 `updateWeightedAvgCost` 函数（4083-4113）。
4. 还原 `refreshInventoryTotals` 第 1403 行 `wac` 取文件值。
5. 还原 app.js 成本页/导入页文案。
6. 还原 db.js 迁移（`wac_history` 表 + `inventory.wac_pending` 列）。

**数据回滚**：
- `wac_history` 表为纯新增，回滚代码后该表可保留（无害）或 `DROP TABLE wac_history;`。
- `inventory.wac_pending` 列回滚后可保留（默认 0，无副作用）或 `ALTER TABLE inventory DROP COLUMN wac_pending;`（SQLite 需重建表，谨慎）。
- 关键风险：本设计**实施前**不得运行旧 `update-weighted-avg`（否则又写 available_qty）。回滚后库存数据一致性由「未再执行违规写入」保证；若实施期间已对某 CI 跑过新逻辑，需对照实施前副本定点核对 RDM731 类既有行（参照 SYS-E2E-02 安全副本流程）。

## 14. 针对性测试清单（仅本轮范围，不混其它缺陷）

1. **成本确认不写库存（核心 P1-03）**：对一个测试 CI 跑 `update-weighted-avg`，断言：
   - `inventory.available_qty` **不变**、`weighted_avg_cost` **不变**、`inventory_value` **不变**；
   - `skus.weighted_avg_cost` **不变**；
   - `wac_history` 新增 1（或 N）条 `confirmation_status='confirmed'`，`new_avg_cost` 公式正确，`version_no` 递增。
2. **allocate 不再写成本**：跑 `allocate`，断言 `skus`/`inventory` 的 `weighted_avg_cost`/`inventory_value` 在 allocate 前后不变（仅 `cost_allocations` 更新）。
3. **ERP 导入投影正确**：对该 SKU 执行 ERP 当前库存导入，断言：
   - `available_qty = 文件数量`；
   - `weighted_avg_cost = latestConfirmedWac`（**非**文件值）；
   - `inventory_value = 数量 × 最新已确认 WAC`；
   - 三字段在同一行更新（无半更新）。
4. **无已确认 WAC 的 ERP 导入**：对一个无 CI 的 SKU 导入，断言 `available_qty` 更新、`weighted_avg_cost` 保留旧值、`wac_pending=1`。
5. **版本追加不覆盖**：对同一 CI 二次 `update-weighted-avg`，断言 `wac_history` 出现 `version_no+1` 新行，旧行不变。
6. **回归（不受影响）**：出库 / 盘点 / 手动调整 / 作废 仍正确更新 `available_qty` 及相应 `inventory_value`（不引入新口径）。
7. **CI 关联**：`wac_history WHERE ci_no=?` 能查回该 CI 全部版本。
8. **显示规则**：成本页在「已确认未导入」状态下显示指定提示文案；库存总表不显示半更新状态。

> 测试数据须带 `E2E2-`/`P1-03-` 标识，使用独立 SKU 或在安全副本机制下执行；本轮设计稿**不执行**上述测试。
