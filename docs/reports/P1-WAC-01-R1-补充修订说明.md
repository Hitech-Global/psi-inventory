## 三、汇率快照粒度设计

同一次 WAC 确认可能包含：USD 货款、USD 国际运费、IDR 本地费用、不同付款日、不同 rate_type、不同汇率来源。仅在一行 `wac_history` 存一个 `exchange_rate` **不构成完整闭环**。

### 3.1 四种粒度对比

| 粒度 | 说明 | 优点 | 缺点 |
|---|---|---|---|
| 1. CI 级快照 | 一次确认存一条快照，含全部汇率组合 | 简单 | **丢失多维事实**：无法表达同 CI 内多币种 / 多付款日 / 多 rate_type；不可追溯单笔费用汇率 |
| 2. 费用级快照 | 每笔费用（货款 / 运费 / 各本地费）各一条快照，记录 source/target/rate/rate_type/rate_date/rate_source/snapshot_id | 可追溯、粒度适中、贴合"每费按自身冻结日期换算" | 同一汇率被多 SKU 引用时会重复——可用去重 upsert 解决 |
| 3. 分配行级快照 | 每个 SKU 分配行都内嵌汇率 | 行级最细 | **重复爆炸**：同汇率在多 SKU 行重复存储，不可取 |
| 4. wac_history 汇总证据 | 汇总行保存不可变汇率事实引用（snapshot_id 列表 / 汇率指纹），不重复存原始汇率 | 无冗余、可审计 | 自身不存原始汇率，须依赖费用级快照存在 |

### 3.2 推荐设计（最小完整闭环）
- **费用级快照为最小不可变单元**：新增 `exchange_rate_snapshots` 表，每一笔进入成本的费用（货款 / 各运费 / 各本地费）生成一条**不可变**快照（参照 wac_history 的 `is_locked=1` 保护，禁止 UPDATE/DELETE 已锁定行）。
- **去重复用**：同一 `(source_currency, target_currency, rate_type, rate_date, rate_source)` 组合只生成一条 snapshot（upsert），多 SKU 引用同一 snapshot_id，**避免每行重复创建**。
- **wac_history 保存汇率证据引用而非原始汇率**：新增列（见原报告 + P1-WAC-07）记录 `source_currency / local_currency / exchange_rate / rate_type / rate_date / rate_source / exchange_rate_snapshot_id`（或 `snapshot_ids` 列表）。
- **追溯能力**：从任意 `wac_history` 行 → `snapshot_ids` → 反查每笔成本来源及其汇率事实（原币、本币、汇率、日期、来源、rate_type），满足历史重放与审计。

## 四、换算与分摊顺序（冻结建议）

必须**明确先后顺序**，不得只写"每笔费用换算"。

### 4.1 两种候选方式
- **甲：先换算成本国货币，再分摊**
  每笔成本先按各自锚点汇率换算为目标国本币 → 同一 `(sku + country + warehouse)` 的本币成本汇总 → 按数量权重分摊到 SKU。
- **乙：先按原币分摊，再逐行换算**
  成本在原币维度按数量分摊到 SKU → 每个分配行用各自汇率换算为本币。

### 4.2 对比分析
| 维度 | 甲（先换算后分摊） | 乙（先分摊后换算） |
|---|---|---|
| 总额守恒 | 好：换算在汇总前完成，分摊仅在本币内做数量权重 | 差：每行独立四舍五入，尾差分散，总额可能不守恒 |
| 同一费用分到多 SKU 精度 | 可控：尾差仅在分摊步产生，可归集到数量最大行或显式尾差列 | 弱：尾差分散到每行，难以回拢 |
| 同一费用分到不同国家 | 需先按国家归属拆分成本或按国家分别换算，逻辑清晰 | 混乱：原币分摊后不同国家行用不同汇率，难保证一致 |
| 审计 / 历史重放 | 强：每笔成本换算后金额确定，可独立重放 | 弱：需同时追溯分摊比例 + 汇率，复杂 |
| 符合冻结口径 | 符合"WAC 使用本国货币" | 易在中间态出现原币混算 |

### 4.3 推荐冻结
**采用甲（先换算成本国货币，再分摊）**。
- 尾差处理：分摊尾差归入数量最大分配行，或设显式 `rounding_diff` 列，禁止随机散落。
- 精度：用**整数缩放**（本币最小单位整数，如分）计算，避免 REAL 浮点累计误差（呼应原报告风险 11/12）；最终展示再除。

## 五、直接汇率与交叉汇率规则

1. **同币种**：`exchange_rate = 1` 仍**生成快照**（保留证据，rate_type 同该成本类型），便于审计与重放，不得跳过。
2. **优先直接汇率**：使用 `from_currency = source`、`to_currency = target` 且 `rate_type` 匹配的 `exchange_rates` 行。
3. **无直接汇率时允许交叉汇率**，但须经显式规则，**不得静默缺省**。
4. **统一桥接币种**：建议固定为 **USD**（或 Final V1.0 指定锚点币）作为唯一桥接币；禁止任意桥接。
5. **交叉汇率须保存组成汇率**：两段各自 `snapshot_id` + 计算方向 + 组合 rate，不得只存结果值。
6. **直接 + 交叉同时存在**：优先**直接汇率**（路径最短、误差最小、来源最可信）。
7. **禁止自动选择任意最短路径**：只允许经唯一指定桥接币的确定路径，禁止图搜索任意最短路径。
8. **rate_type 一致性**：交叉路径每一段**必须保持同一 rate_type**（如均为 settlement 或均为 freight）；段间 rate_type 不同视为不可接受，须业务裁断。
9. **倒数使用**：保存**原始方向**（from→to）与**计算方向**（to→from）及 `1/rate` 计算值，标记 `computed_inverse=1`，保留原始快照引用，不丢方向信息。
10. **舍入与精度**：计算用整数缩放；交叉汇率保留足够中间精度，最终四舍五入规则统一（银行家舍入或半上调，待冻结），不得 REAL 直接浮点累计。

## 七、修正"库存已污染"的证据边界

### A. 已确认事实
- `wac_history` 中**已经存在币种混算结果**（new_avg_cost 货币语义错误，实证 63.6667 / 60 / 68.0769 等 USD 量级值）。此为已确认。

### B. 需继续用只读证据确认的事实（本补充已做如下核验）
- **ERP 库存导入是否已发生**：**是** — `inventory.weighted_avg_cost` 在 388/401 行有值，说明 ERP 投影代码路径曾被运行。
- **哪些 inventory 行已实际读取这些错误 wac_history**：无直接外键；按 `(sku_code, country, warehouse)` 匹配。数值比对结果：仅 **2 行** `inventory.weighted_avg_cost` 数值等于某 `wac_history.new_avg_cost`（60/63/68 量级），但该量级远小于主流 IDR 量级（数万~数十万），相关性极低，**不能作为"已污染"证据**。
- **当前 inventory.weighted_avg_cost 是否已被错误值覆盖**：**无直接 DB 证据**支持"全部已被覆盖"。当前主流值为 IDR 量级，与 junk（USD 量级）不符，更可能是早期独立 ERP 投影（使用 original_avg_cost 的 IDR 值）结果，而非来自 junk wac_history。

### 修正表述（强制）
- **不得写成"全部库存已被污染"**。
- 只能写为：**"存在通过 ERP 导入投影污染库存的确定代码风险"**——即一旦运行新版投影逻辑读取 junk `new_avg_cost`（USD 量级）并写入 `inventory.weighted_avg_cost`（应为 IDR），即发生污染；该风险由代码路径确定存在，但当前 DB 无证据表明已大规模实际发生。
