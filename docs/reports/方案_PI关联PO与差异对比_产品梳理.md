# 方案：PI 关联 PO 与 PO↔PI 差异对比（仅 PI 页面，最小产品梳理）

> 范围：只梳理 PI 这一步。不改代码、不落库、不接审批中心 / CI·PL / 订单预测 / 停采·失真·多维周转·三页口径·实时回写。
> 方向前提（用户确认）：PO 审批通过后**不自动生成 PI**；PI 仍在 PI 页手动新建并关联 PO；供应商给的 PI 不一定严格按 PO，重点是把**差异看清楚、可确认、可追溯**。

## 1. PI 新建页保留「关联 PO」

- 保留现有「关联 PO」下拉（仅列出 `po_status='approved'` 的 PO）。
- 选中后：供应商 / 币种自动带出（现有 `loadLOForPI` 逻辑），**不自动写入 PI 明细**，改为在下方「PO 参考区」只读展示原始明细（见第 2 点）。
- 理由：保留"手动新建 + 关联"的方向，不引入自动生成，符合"PO 与 PI 不强制一一对应"。

## 2. 关联 PO 后显示「PO 原始明细」参考区

在 PI 新建/编辑页，选中 PO 后新增一块**只读**参考区（数据来源复用 `GET /api/purchase-orders/:id`，与审批详情同源，**不新造接口**）：

| 列 | 来源 | 说明 |
|---|---|---|
| SKU | `purchase_order_items.sku_code` | PO 原始 |
| PO 数量 | `po_qty` | PO 原始 |
| PO 单价 | `unit_price` | PO 原始（PO 若有） |
| PO 金额 | `po_qty × unit_price` | PO 原始（PO 若有） |

- 该区**只读**，仅作录入/导入的对照基准，不参与保存。
- 与现有"PI 录入区"分区显示，避免把 PO 值与 PI 值混在同一可编辑表里造成误改。

### 2.1 PO 单价的数据来源约束（重要，已确认）

- **PO 数量**直接取 PO 明细 `purchase_order_items.po_qty`，无依赖。
- **PO 单价 / PO 金额**：
  - 直接读 PO 明细里**已有的** `unit_price` 字段（即 `GET /api/purchase-orders/:id` 返回的 `items[].unit_price` / `po_amount`）。
  - 若当前 PO 明细里**没有**单价（字段为空或 0），则 PO 参考区对应单元格**留空或显示 0**，**不做任何反算、不报错**。
- ⚠️ **不依赖库存管理 - SKU 主数据**：PO 参考区的单价只取自 PO 明细本身，**不回查 SKU 主数据表的单价**（SKU 主数据页尚未加单价字段，本轮**不扩到 SKU 主数据改造**）。即：PO 明细有单价就显示，没有就空着，绝不顺手去改 SKU 主数据结构。
- 同理 PO 金额 = `po_qty × unit_price`（仅当单价存在时），单价缺失则金额留空/0。

## 3. PI 页面增加「供应商 PI 导入」（填充当前 PI 明细）

- 在 PI 新建/编辑页新增按钮「📥 导入供应商 PI」，作用对象是**当前这张正在建/在编的 PI**（区别于现有"批量新建 PI"导入）。
- 导入模板列（最小集）：`SKU / PI数量 / 单价 / 折扣 / 金额`。
  - 折扣：供应商常给行级折扣，需支持（见第 4 点金额口径）。
  - 金额：允许导入时直接给金额，也允许由 `PI数量 × 单价 × (1-折扣)` 反算；以导入值为准，缺失时反算。
- 导入后填充「PI 录入区」的对应行（SKU 匹配则覆盖数量/单价/折扣/金额，新增 SKU 则追加行）。
- 数据结构改动：需在 `proforma_invoice_items` 新增 `discount REAL DEFAULT 0` 列（行级折扣）；导入模板 `DOC_TEMPLATES.pi` 增加「折扣」表头。
- 现有批量导入（`batch-import`）保留不动，两者并存：批量导入=新建多张 PI；供应商 PI 导入=填充单张 PI 明细。

## 4. 系统自动做 PO vs PI 差异对比

差异引擎**不存冗余字段**，按 SKU 实时 join 计算（PO 项取实时 `purchase_order_items`，PI 项取当前 `proforma_invoice_items`）：

| 差异维度 | 计算口径 |
|---|---|
| 数量差 | `PO数量 − PI数量`（正=PI 少; 负=PI 多） |
| 单价差 | `PO单价 − PI单价` |
| 金额差 | `PO金额 − PI金额`（PI 金额含折扣：`PI数量 × PI单价 × (1−折扣)`） |
| 缺少 SKU | 在 PO 中、但 PI 中没有 → 提示"PO 有 PI 缺" |
| 新增 SKU | 在 PI 中、但 PO 中没有 → 提示"PI 新增（PO 无此 SKU）" |
| 差异状态 | 每行标记：一致 / 仅数量差 / 仅单价差 / 量价均差 / 缺SKU / 新增SKU |

- 金额口径统一用"含折扣的 PI 金额"与"PO 金额"对比，避免折扣导致的虚高/虚低差异误报。
- 差异可在「PI 录入区」下方实时展示，也可在「PI 详情」(`viewPI`) 里增加"差异对比"区——两者共用同一引擎函数。

## 5. 交互结构判断（推荐方案）

**推荐：分区结构 + 合并对比表**，而非三块完全独立。

```
┌─────────────────────────────────────────────┐
│ PI 新建 / 编辑                                  │
│ [关联 PO ▼]  [供应商 ▼]  [PI日期] …            │
├─────────────────────────────────────────────┤
│ ① PO 参考区（只读，关联 PO 后显示）            │
│   SKU | PO数量 | PO单价 | PO金额              │
├─────────────────────────────────────────────┤
│ ② PI 录入/导入区（可编辑 + 📥导入供应商PI）    │
│   SKU | PI数量 | 单价 | 折扣 | 金额 | 操作    │
├─────────────────────────────────────────────┤
│ ③ 差异对比区（合并对比表，实时/点"对比"生成） │
│   SKU | PO量 | PI量 | 量差 | PO单价 | PI单价 │
│       | 单价差 | PO金额 | PI金额 | 金额差 | 状态│
└─────────────────────────────────────────────┘
```

- 为什么不用"三块完全独立"：PO 参考区天然是只读上下文，PI 区是工作区，差异区是结果——三者分区最清晰，且差异区用**一张合并对比表**最高效（一行一 SKU，左右对照 + 差异列），比"再开一个仅差异表"更省眼。
- 差异区可默认实时（录入/导入即算），也可放"生成差异对比"按钮按需触发（首版建议**实时**，零额外点击成本）。

## 6. 单张 PO 关联（最小）+ 多张 PO 预留

- **本轮**：仅支持单张 PO 关联（沿用现有 `related_po_id` 单值字段，不改表结构主形态）。
- **数据结构预留多张**：
  - 差异引擎的输入参数设计为「PO id 列表」（`poIds: string[]`），本轮只传 1 个；PO 参考区 = 该列表下所有 PO 项的并集（按 SKU 合并数量）。
  - 后续若要多张 PO：新增关联表 `pi_po_links(pi_id, po_id, note)`，把 `related_po_id` 的语义迁移到该表；**本轮不建此表**，仅在引擎签名与 PO 参考区取数上预留"可接收数组"。
  - 这样多张 PO 是**纯增量改动**，不回改本轮逻辑。

## 7. 边界与不改清单（明确保证）

- 不动：审批中心 / 订单预测 / CI·PL / 停采·失真·多维周转·三页口径·实时回写 / 采购链状态机 / submit-approval·approve。
- 不引入：PO 审批通过后自动生成 PI（明确不做）。
- 不新造接口：`GET /api/purchase-orders/:id` 已可复用作 PO 参考区数据源；差异引擎为前端纯计算（或后端一个只读对比接口，可选）。
- 可选后端增强（非必须，待拍板）：`GET /api/proforma-invoices/:id/diff` 返回对比结果 JSON，便于"差异状态"在列表/详情统一消费；首版可纯前端算。

## 落地决策（2026-07-11 已拍板，可据此开改）

1. **折扣口径**：行级折扣 `discount` 用 **比例（0~1）**，不另做"折扣额"。
2. **差异区触发**：**实时计算**（录入 / 导入即算，零额外点击），不靠按钮触发。
3. **差异结果落库**：首版**不落库**——只实时算差异，不做 `pi_diff_snapshots` 追溯快照（范围做轻）；后续若需追溯再单独加。
4. **供应商 PI 导入 vs 现有批量导入**：**不共用模板**——供应商 PI 导入模板独立（含"折扣"列），且作用于"当前这张在编 PI"，与"批量新建 PI"并存不冲突。
5. **多张 PO 关联**：本轮**不建 `pi_po_links` 表**，仍走单张 `related_po_id`；但差异引擎入参与 PO 参考区取数**按"PO id 数组"设计**，后续多张 PO 为纯增量改动。
6. **PO 单价来源约束**：PO 参考区单价**只取 PO 明细自身 `unit_price`**，**不依赖 SKU 主数据**（该页尚无单价字段，本轮不扩到 SKU 主数据改造）；PO 明细无单价则留空/0，不反算、不报错。
