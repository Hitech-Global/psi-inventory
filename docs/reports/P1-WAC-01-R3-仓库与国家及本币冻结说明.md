## 一、新增冻结业务规则（作为 P1-WAC 后续设计的强制前提）

### 规则 11：仓库与国家的归属关系
- **一个仓库只能属于一个国家。**
- **一个国家可以拥有多个仓库。**
- **仓库不得跨国家归属**（即同一仓库的 `country` 必须唯一，不可同时归属两个及以上国家）。

### 规则 12：本国货币由国家唯一确定，禁止人工选择目标币种
- **本国货币由库存国家唯一确定**，映射固定：
  - 印度尼西亚 → IDR
  - 马来西亚 → MYR
  - 泰国 → THB
- **国家确定后，目标本币自动唯一确定**，不存在"根据国家再选币种"的中间步骤。
- **后续所有 WAC 计算、成本换算、库存价值计算，均以该唯一目标本币执行。**
- **不设计目标币种人工选择功能**（前端 / 接口 / 配置均不提供 WAC 目标币种手动切换）。

> 与 R2 前提 4 一致：同一 CI 目标本币唯一；本规则进一步将"国家→本币"固化为不可人工干预的派生关系，并以"仓库单国家"作为国家归属的实物锚点。

## 二、只读证据（支撑冻结的当前模型事实）

以下为本次只读核验结果（不修改任何数据）：

- **仓库→国家关系已在模型中建模**：存在 `warehouses` 表，含 `country_id`、`country_name` 列，结构上支持"一个仓库归属一个国家"。
- **当前数据已符合规则 11**：`inventory` 中按 `warehouse` 分组，无任一仓库映射到 >1 个国家（无跨国家仓库）。
- **但存在国家键不一致（须 P1-WAC-02 解决）**：
  - `warehouses.country_name`：`Indonesia` / `Malaysia` / `Thailand` / `Vietnam` / `中国`
  - `inventory.country`：混用 `印度尼西亚` 与 `Indonesia`（同一国两种写法）
  - `commercial_invoices.country`：`印尼` / 空（`""`）
  - **三套国家命名并存**，且 `warehouses` 含 Vietnam、China，不在 ID/MY/TH 本币映射内。
- **结论**：规则 11 的数据基础已具备；规则 12 的"国家→本币"映射**必须基于单一规范国家键**（建议 `country_id` 或统一 code），不能依赖自由文本 `country_name`；Vietnam / China 等未映射国家**不得被静默赋予 WAC 本币**，须显式排除或单独裁断。

## 三、对前述设计边界的同步影响

### 3.1 强化 R2"CI 单国家"前提
- 仓库是国家的实物锚点：CI 的仓库 → 唯一国家 → 唯一本币（规则 11 + 12）。
- 故 R2 前提 1（一张 CI 只对应一个库存国家）在数据上可由"CI 仓库单国家"推导并校验，无需另设 CI 级跨国字段。

### 3.2 国家→本币映射须前置冻结（并入 P1-WAC-02）
- P1-WAC-02 除既有"国家映射键归一化"外，须明确：
  - 规范国家键（如 `country_id`）；
  - 规范键 → {IDR, MYR, THB} 的唯一映射表；
  - 未映射国家（Vietnam / China 等）在 WAC 链路中的显式拒绝/排除策略；
  - 任何自由文本 `country` / `country_name` 在 WAC 计算前必须先归一化为规范键。

### 3.3 禁止目标币种人工选择（设计约束）
- 成本确认页、汇率页、WAC 计算接口：**不提供**目标币种下拉 / 输入。
- 若现有任何 UI / 接口存在 WAC 目标币种手动选项，须在 P1-WAC 实施设计中列为"移除 / 禁用"项（仅设计，不本轮实现）。
- 本币完全由"仓库→国家→本币"派生，对业务用户透明。

### 3.4 不影响 P1-WAC-03~09 其余设计
- 汇率快照仍按每笔成本来源独立锁定（R2 §2.4 / R1 §三）。
- wac_history 仍保留 `snapshot_ids` 多引用（R2 §2.5）。
- 换算与分摊仍在单一国家内部进行（R2 §2.1、§2.6）。
- 仅新增"仓库单国家"作为国家归属锚点，不引入跨国家复杂度。
