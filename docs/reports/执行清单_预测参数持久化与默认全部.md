## 〇、先回答你最关心的一条：「保存一次，下次同维度自动命中，不用重复设置」

**这条现在的实现已经天然成立，本轮不会破坏它，还会让它更明确。** 机制拆开讲：

### 1. 规则长期保存在 dim_default_config —— 已成立
- 保存走 `saveRpParams()` → `POST /api/system-config`（`app.js:4151`），写入 `system_config` 表的 `dim_default_config` 键（JSON 数组）。
- `system_config` 是 SQLite 持久表，不是内存/会话态。**关服务、重启、换浏览器都不丢**。

### 2. 下次进页面、筛到同维度会自动命中 —— 已成立
- 命中判断在后端 `getDimTurnover()`（server.js），读的就是同一张 `dim_default_config`。
- 你重新计算时，后端按 `品牌|国家|仓库` 评分命中该规则，取其 online/offline 周转。**只要维度字符串一致就命中，与"这次是否重新设置过"无关。**

### 3. 打开弹窗优先显示"当前命中的已有规则" —— 已成立 + 本轮强化
- `openRpParams()`（`app.js:4021`）每次打开都重新 `GET /api/system-config` 拉最新规则 → `resolveDimHit()` 前端镜像同一套评分 → 顶部"当前命中到的已有规则"只读块显示 品牌/国家/仓库/线上/线下/优先级 6 项，且把该值**预填**进输入框。
- 也就是说：你筛到 Redragon/印尼 且它已有规则，打开弹窗**输入框里就是上次存的值**，只读块也显示它——你一眼看到"已有规则"，不需要重设。
- 本轮强化点见第四节 D：全通配上下文下只读块的显示口径修正，避免误导。

### 4. 只有想改时才需要再保存一次 —— 已成立
- 不打开弹窗 / 不点保存 → `dim_default_config` 不变。
- 只有你改了输入框并点"💾 保存当前维度规则"，才对该维度 upsert；其它维度规则原样保留（`saveRpParams` 里 `filter` 只删同键，`push` 只加当前键）。

> 结论：持久化这条是**现状即满足**，本轮 4 项改动都不触碰保存/读取链路，只优化"默认状态"与"弹窗内呈现方式"，所以不会引入"每次都要重设"的倒退。

## 二、默认筛选改「全部」

### 现状（问题）
- `loadRpFilterOptions` 2769-2772：国家强制默认 印尼/印度尼西亚。
- `onRpCountryChange` 2806-2808：品牌强制默认 Redragon。
- 结果：一进页面就带 **国家=印尼 + 品牌=Redragon** 的非中性上下文。

### 改后
- 国家 = `''`（全部）、品牌 = `''`（全部）、仓库 = `''`（全部，本就如此）。
- 保留"记住用户上次手选值"逻辑（`prevCountry/prevBrand` 分支不动），只去掉"没选时强制填某值"的兜底分支。
- 数据加载不受影响：空国家=查全部，`loadRpSummary()/loadRp()` 照常。

### 价值
- 中性起点。"当前筛选上下文"只有你主动选了才非中性 → 预测参数设置关联上下文时不会"替你预填一组你没选的维度"。

## 三、弹窗结构：只读筛选参考 + 可编辑保存对象

打开"⚙ 预测参数设置"后，从上到下：

```
[销量统计周期]  近60/90/120天           ← 不变

──────────────────────────────
① 当前页面筛选（只读参考）
   [品牌: 全部] [国家: 印尼] [仓库: 全部]   ← 只读横幅，纯参考

② 本次保存的规则对象（可编辑）           ← 新增，保存以这里为准
   品牌 [Redragon      ]  ← 预填①的筛选值，可改
   国家 [印尼          ]  ← 预填①的筛选值，可改
   仓库 [(空=通配)     ]  ← 预填①的筛选值，可改
   线上周转 [ 4 ]   线下周转 [ 4 ]   ← 预填命中规则值
   提示：（当前维度已有规则，修改将覆盖它 / 暂无命中，保存将新增）

③ 当前命中到的已有规则（只读）
   命中的品牌 / 国家 / 仓库 / 线上周转 / 线下周转 / 命中优先级  ← 6 项，保存前看清覆盖谁

④ [全通配红色警告]（仅当②三处都空时出现）

⑤ ⚙ 高级设置（默认折叠）：全部规则自由表
──────────────────────────────
[取消] [💾 保存当前维度规则]
```

**关键差异（相较上一版）**：
- 上一版：规则三维度**隐式**取自筛选下拉，不可单独改。
- 本版：规则三维度是 ② 里的**可编辑输入框**，默认预填①的筛选值，**保存以②为准**。即使你忘了筛了什么，也能在②里看清/改正"到底存成哪组维度"。

## 四、保存逻辑（saveRpParams 改动）

### A. 保存来源改为读 ② 可编辑框
```
旧：var ctx = currentRpContext();              // 读 rp-b/rp-c/rp-w 下拉
新：var ctx = {                                 // 读 ② 可编辑输入框
      brand:    (#rp-rule-brand).value.trim(),
      country:  (#rp-rule-country).value.trim(),
      warehouse:(#rp-rule-warehouse).value.trim()
    };
```
其余（周转正数校验、upsert filter+push、高级区合并去重、POST）**完全不变**。

### B. upsert 保持不变（保证"只改当前维度，其它规则不丢"）
```
key = brand|country|warehouse
rules = 现有规则.filter(r => key(r) !== key(new))   // 删同键
rules.push(new)                                     // 加当前
合并高级区其它维度行（去重，当前维度优先）
POST dim_default_config = rules
```

### C. 全通配二次确认（不变，你已确认保留）
当 ② 三处都为空时，`confirm()` 强阻断：
> **「这会保存为全通配规则，作用于所有未被更具体规则覆盖的维度。确认保存吗？」**
弹窗内另有红框：「当前 品牌/国家/仓库 均为『全部』。保存后将生成全通配规则……」

### D. resolveDimHit 全通配显示修正（小修）
- 问题：② 三处全空时，旧 `resolveDimHit` 会匹配所有规则并返回评分最高的一条（可能是 Redragon 的具体规则），③ 只读块显示它 → 误导。
- 修正：② 三处全空时，只在规则里找 `品牌=国家=仓库=空` 的全通配规则显示；若无则 ③ 显示"无全通配兜底规则（保存后将新增）"。与全通配警告自洽。

## 五、三种筛选场景 → 保存成什么（设线上=A、线下=B）

> 注意：现在保存以 ②「可编辑规则对象」为准（默认预填①筛选值）。以下假设你未在②里手改维度。

| ① 页面筛选 | ② 预填规则对象 | 保存结果 | 命中优先级 | 提示 |
|---|---|---|---|---|
| 品牌=Redragon / 国家=印尼 / 仓库=全部 | Redragon / 印尼 / 空 | `{Redragon, 印尼, "", A, B}` | 品牌+国家（得分6） | 无 |

## 六、持久化体验闭环（本清单核心承诺）

一次完整流程验证"存一次、下次自动命中、不用重设"：

1. 进页面 → 三筛选默认全部（中性）。
2. 手选 品牌=Redragon / 国家=印尼。
3. 打开预测参数设置 → ② 预填 Redragon/印尼 → 填线上=4/线下=4 → 保存 → 点重新计算。
4. **关浏览器 / 重启服务 / 换设备**。
5. 重新进页面 → 手选 品牌=Redragon / 国家=印尼。
6. 打开预测参数设置 → **③ 只读块显示 Redragon/印尼/线上4/线下4/品牌+国家**，②输入框已预填 4/4 → **无需重设**。
7. 直接点重新计算 → 后端 `getDimTurnover` 命中同规则，周转=4。

> 关键：第 4 步的重启不影响，因为规则在 SQLite `system_config`，不是会话态。
