## 0. 适用范围与禁止事项

本规则仅描述成本与汇率的计算口径、状态分离、金额分类、触发条件、生命周期与历史数据处理，不涉及任何实现（代码、数据库表结构、接口、字段、页面）。所有落地动作待用户最终确认并进入 DB 设计阶段后再行实施。本轮为纠偏定稿与全文交付，不再新增业务规则。

## 1. 名词与范围

- **本国货币 LC**：按 CI 目的国计价的货币，即 IDR（印尼盾）、MYR（马来林吉特）、THB（泰铢）。
- **人民币 RMB**：系统中人民币记为 `RMB`（注意：系统不使用 `CNY` 标识，全系统统一用 `RMB`）。
- **USD**：常见外币。
- **成本确认 Cost Confirm**：`cost_confirmed = 1` 的业务状态，代表该批次库存成本已确定并锁定快照。
- **成本结算日**：Cost Confirm 时为本批次确定的**统一折算日**，用于把纳入成本的外币金额统一折算为本币，形成批次正式落地成本（即原「成本确认日」的统一术语）。
- **汇率快照 Snapshot**：在成本结算日（批次口径）或费用实际付款完成日（财务口径）锁定的 `from → to` 汇率值 + 汇率日期 `rate_date`。两类快照分属不同层次，见 §15。
- **本币 WAC**：以本国货币计价的库存加权平均成本，存储于 `inventory.weighted_avg_cost`。
- **实时展示汇率**：系统「库存管理 → 库存总表」已存在的实时汇率功能，用于把当前本币库存货值换算成人民币，供中国团队查看当前库存规模。
- **正常业务 CI**：系统日常采购 → PI → CI 流程产生的 CI。
- **历史批量导入 CI**：通过「历史 CI 批量导入」进入系统的历史 CI（历史数据迁移 / 初始化）。其默认影响范围见 §18，**不自动参与运营 WAC**。
- **原库存导入**：`commercial_invoices.original_inventory_imported = 1`，代表该 CI 对应实际入库数量已导入，可作为 WAC 基数。
- **成本清单**：本批次参与成本确认的费用项集合，每项须标记状态（已纳入 / 不适用 / 允许后补 / 必须等待），见 §22。

## 2. 两类汇率（必须严格区分）

### 2.1 A. 成本汇率快照（Cost Rate Snapshot，批次口径）

**用途**：批次 WAC 成本折算（CI 货值、参与 WAC 的外币费用统一按**成本结算日**折算）、历史人民币成本、历史成本趋势。

**规则**
- 在**成本结算日**（Cost Confirm 确定的统一结算日）锁定汇率值与汇率日期。
- 锁定后**不得随市场汇率变化**。
- **不得被库存总表实时汇率覆盖**。
- **不得回写或改变已确认的本币 WAC 和历史成本**。

### 2.2 B. 实时展示汇率（Real-time Display Rate）

**来源**：系统「库存管理 → 库存总表」已存在的实时汇率功能。

**用途**：库存总表当前人民币货值、当前本币库存价值换算成人民币、管理层查看当前人民币等值。

**规则**
- 可由系统自动获取最新汇率。
- 可以动态变化。
- 只用于展示和当前估值。
- **不参与 WAC**。
- **不改变历史人民币成本**。
- **不改变 CI 成本、费用成本或付款金额**。
- **不回写本币 WAC**。

> 关键结论：两类汇率并存。成本汇率快照负责「历史与成本」口径（且批次口径统一用成本结算日），实时展示汇率负责「当前估值展示」口径，二者互不覆盖、互不回写。

## 3. 两种人民币金额（必须严格区分）

### 3.1 A. 历史人民币成本（Historical RMB Cost）

- **含义**：本币成本按**成本结算日**锁定的汇率换算出的人民币成本。
- **用途**：历史采购成本、费用趋势、批次成本复盘。
- **特点**：历史稳定，**不随实时汇率变化**。

### 3.2 B. 当前人民币等值（Current RMB Equivalent）

- **含义**：当前本币库存价值按最新实时汇率折算出的人民币金额。
- **用途**：库存总表当前人民币货值、当前库存规模查看。
- **特点**：可以动态变化，**只用于展示**，**不作为 WAC 或历史成本依据**。

### 3.3 示例

| 项目 | 值 |
|------|----|
| 本币 WAC | 220,000 IDR |
| 成本结算日汇率 | 1 RMB = 2,200 IDR |
| 历史人民币成本 | 100 RMB |
| 当前实时汇率 | 1 RMB = 2,300 IDR |
| 当前人民币等值 | 95.65 RMB |

两个结果都**可以**存在，但含义不同，**禁止互相覆盖**。

## 4. 七条原基线（V1.0，全部有效）

1. **本币成本本位**：库存成本以本国货币（LC）为本位记账，人民币为派生展示货币。
2. **成本确认驱动**：库存成本在 CI 成本结算日（Cost Confirm）后确定，确认前为在途/暂估状态。
3. **本币 WAC 为本**：库存流转使用本币加权平均成本 `weighted_avg_cost`，不依赖实时汇率。
4. **人民币为派生**：人民币金额是基于汇率快照换算的统计值，非唯一成本依据。
5. **落地成本口径**：落地成本 = 货款 + 参与 WAC 的费用，统一以本币归集（按成本结算日折算）。
6. **费用归属明确**：费用是否计入落地成本（WAC）由 `include_in_landing_cost` 决定。
7. **汇率统一来源**：所有业务汇率统一读取 `exchange_rates` 表，已确认业务采用快照锁定。

## 5. 成本确认与付款状态分离（货款未付不阻止成本确认）

- 货款可能有账期，可分多期支付。
- **货款未付清不阻止成本确认**。
- CI 账单金额确定后即可作为货值。
- 成本确认时按**成本结算日**锁定汇率折算成本币货值。
- 应付 / 已付 / 未付属于**财务付款状态**。
- 成本确认属于**库存成本状态**。
- 两者**必须分离**。
- 后续实际付款**不得重新修改已确认库存成本**。

---

## 6. 汇率采用时点（双层次）

- **批次 WAC 成本口径**：纳入成本的外币金额（CI 货值 + 参与 WAC 的外币费用）统一按**成本结算日**快照折算（非 CI 建立时，非任何单笔付款日）。
- **费用财务口径**：每一笔费用在其**实际付款完成日**的汇率快照保存，用于财务付款、现金流、费用趋势、付款复盘（见 §15.A）。
- **费用确认时间** = 实际付款完成（**不是**审批通过、**不是**申请日）。
- 两层次汇率用途不同、可同时并存，详见 §15。

## 7. 是否参与 WAC（include_in_landing_cost）

统一命名「是否参与 WAC」。

- **默认参与**：货款 / 国际运费 / 关税 / 商检 / 清关 / 本地杂费。
- **默认不参与（待最终确认）**：退款折扣 / 内部转账 / 银行手续费 / 不绑定 CI 的通用管理费。

规则：
- 参与 WAC 的费用进入落地成本与本币 WAC（按成本结算日折算）。
- 不参与 WAC 的费用仅作财务记账，不影响库存成本。

## 8. 本币 WAC 公式（两种情形）

### 8.A 新货入库形成 WAC

**第一步：本次入库单位本币成本**

```
本次入库单位本币成本
  = 本次批次本币落地总成本 ÷ 本次实际入库数量
```

**第二步：新本币 WAC**

```
新本币 WAC
  = （原库存数量 × 原本币 WAC + 本次入库数量 × 本次入库单位本币成本）
    ÷ （原库存数量 + 本次入库数量）
```

等价于：

```
新本币 WAC
  = （原库存本币总成本 + 本次入库本币总成本）
    ÷ （原库存数量 + 本次入库数量）
```

### 8.B 仅补录费用，不增加库存数量

```
调整后 WAC
  = （当前库存数量 × 当前本币 WAC + 本次实际分配给当前库存的补录费用本币金额）
    ÷ 当前库存数量
```

**必须明确**
- 本次入库单位成本 **≠** 最终 WAC（8.A）。
- 8.A 必须使用**原库存数量**、**原库存本币 WAC**。
- 8.B 分母**不能再增加本次入库数量**（补录不增加库存）。
- 已销售 / 已出库部分不参与当前库存调整（见 §16、§24）。
- 若当前库存 = 0，补录费用只进入财务与历史成本分析，不影响运营 WAC（8.B 退化为仅记录）。
- 补录费用若需在多 SKU 间分配，分配规则仍属开放点，本轮不自行决定（见 §31）。
- 实时人民币汇率**不得参与**本币 WAC 计算。
- 当前库存导入已提供本国货币 WAC。

## 9. 成本确认锁定规则（永久保存）

成本确认时锁定并永久保存以下信息：

- 成本结算日、确认人、确认权限来源
- 原始金额、原始币种
- 成本结算日汇率快照（from → to rate）、汇率日期
- 本币金额（批次成本本币金额）
- 成本清单逐项状态快照（已纳入 / 不适用 / 允许后补 / 必须等待）
- 是否参与 WAC（include_in_landing_cost）
- 关联 CI、费用类型

锁定后永久保存，**不受后续汇率波动影响**。

---

## 10. 人民币成本冻结

- 人民币成本冻结的是**汇率快照**，属派生统计值，**非唯一成本依据**。
- 历史人民币成本按**成本结算日**锁定汇率换算，**不随实时汇率变化**。
- 当前人民币等值按实时展示汇率换算，**仅用于展示**。

---

## 11. 付款记录不可直接修改（冲销规则）

- 付款记录**不可直接改**，只可**冲销（红字）+ 重生成**。
- 冲销产生红字记录，重生成产生新正确记录。
- 冲销关联与原付款记录保持可追溯。
- 付款冲销只影响**财务付款状态**，**不触发 WAC 重算**，不修改已确认库存成本（若冲销导致货值需更正，走 §16 / §20 / §24 成本调整流程）。

---

## 12. 汇率自动获取与同步规则

- 系统通过第三方 API 自动同步汇率到系统汇率库（`exchange_rates`）。
- 日常不依赖人工维护。
- 所有业务统一读取系统汇率库。
- 成本计算过程中**不得临时直接请求第三方 API**。
- 支持自动补取历史日期汇率。
- 被业务采用的汇率**必须保存为快照**。
- 后续 API 汇率变化**不得影响已确认成本**。
- 库存总表现有实时汇率可使用最新自动汇率做**当前人民币等值**展示。
- 当成本结算日快照缺失时的兜底原则，见 §19。
- 汇率库唯一生效与每日去重规则，见 §25。

## 13. 历史 CI 财务维度与运营 WAC 存储隔离

- 历史 CI（含历史批量导入 CI）的财务维度（人民币成本、费用明细）与运营 WAC **分开存储**。
- 运营 WAC 用于日常库存成本流转。
- 财务维度用于历史复盘与报表。
- 二者通过 CI / 批次关联，但**不互相回写**。
- 历史批量导入 CI 的默认影响范围与「成本初始化 / 成本衔接模式」见 §18。

## 14. 八类金额总表（完整金额分类）

| # | 金额 | 源头 / 汇率层 | 用途 | 是否参与 WAC |
|---|------|--------------|------|--------------|
| 1 | 原始业务金额 | CI/费用账单原币（源头） | 业务源头、对账基准 | — |
| 2 | 实际付款金额 | 付款原币（可能分期/部分） | 财务收付、现金流 | 否（财务） |
| 3 | 付款日本币金额 | 付款日快照 → LC | 财务付款、费用趋势、付款复盘 | 否（财务） |
| 4 | 付款日人民币金额 | 付款日快照 → RMB | 财务付款、费用趋势（人民币视角） | 否（财务） |
| 5 | 批次成本本币金额 | 成本结算日快照 → LC | **WAC 落地成本**（批次口径） | 是（参与） |
| 6 | 历史人民币成本 | 成本结算日快照 → RMB（稳定） | 历史采购成本、费用趋势、批次复盘 | 否（派生展示） |
| 7 | 当前人民币等值 | 实时展示汇率 → RMB（动态） | 库存总表当前货值、管理层查看 | 否（仅展示） |
| 8 | 当前本币 WAC | 两步法加权（LC） | 库存流转、出库成本 | 是（主体） |

**解释与禁止项**
- **源头金额**：#1 原始业务金额是业务起点；#2 实际付款金额是财务收付起点。
- **用于财务**：#2 / #3 / #4 服务于财务付款、现金流、费用趋势、付款复盘（付款日口径，见 §15.A）。
- **用于 WAC**：#5 批次成本本币金额与 #8 当前本币 WAC 是库存成本主体（成本结算日口径，见 §15.B）。
- **用于历史趋势**：#6 历史人民币成本（稳定，不随实时汇率变）。
- **仅用于实时展示**：#7 当前人民币等值（动态，不入账）。
- **各金额不得互相覆盖**：付款日折算金额（#3/#4）不得替代批次 WAC 成本金额（#5）；当前人民币等值（#7）不得回写历史人民币成本（#6）或 WAC（#8）。

## 15. 成本结算日规则（双层次，纠偏核心）

> 本章明确区分「费用付款与费用趋势口径」与「批次 WAC 成本口径」，纠正「按每笔费用付款日自动重算批次初始 WAC」的错误。

### 15.A 费用付款与费用趋势口径（财务层）

每一笔费用实际付款完成后，按**自身付款日**汇率保存：

- 原币金额
- 原币币种
- 付款日本币金额
- 付款日人民币金额
- 付款日汇率快照
- 付款日期

**用途**：财务付款、现金流、费用趋势、付款复盘。

### 15.B 批次 WAC 成本口径（成本层）

Cost Confirm 时为该批 CI 确定一个统一的**成本结算日**（确定口径见 §27）。本次纳入成本确认的：

- CI 货值
- 外币运费
- 外币关税
- 外币商检
- 外币清关费
- 其他参与 WAC 的外币费用

统一按**成本结算日**汇率折算成本币，形成该批次正式落地成本。

若费用本身即是本国货币：本币成本金额直接等于原币金额，**不需要换算**。

### 15.C 必须明确的六条

1. 付款日折算金额服务于**财务和费用趋势**。
2. 成本结算日折算金额服务于 **WAC**。
3. 两个金额用途不同，**可以同时存在**。
4. **不能**使用付款日折算金额直接替代批次 WAC 成本金额。
5. **不能**让每一笔费用付款后自动重算该批次**初始 WAC**。
6. 历史已手工按运费付款日计算的成本**保持原样，不追溯重算**。

## 16. 补录费用规则（前向调整，纠偏）

- **允许进入原 CI 成本**，采用**「成本调整（前向）」**：按 §8.B 对当前库存增量重算新 WAC（生成新版本，见 §30）；已出库 / 已销售部分原 WAC 与历史人民币成本快照**保持不变**（见 §24）。
- 成本清单中标记为「允许后补」的费用，在 Cost Confirm 后追加时走此前向调整。
- 备选分支：若费用与本次到货无关或属期间管理费，进入**独立后续费用科目**，不参与该 CI 的 WAC，仅财务记账与分析。
- 补录费用同样适用 §7 的 `include_in_landing_cost` 判定。
- **历史批量导入 CI 的补录费用**：默认不得借此回写运营库存和 WAC（见 §18）。

## 17. 多笔运费与多币种费用（纠偏）

- 每笔费用在其**实际付款完成日**各自保存付款日快照（§15.A），用于财务与费用趋势。
- **付款日快照不自动重算批次初始 WAC**（§15.C.5）。
- 批次 WAC 在 Cost Confirm 时按**成本结算日**统一折算所有已纳入的外币费用（§15.B）。
- 不同币种、不同付款日的费用各自锁定自己的付款日快照（财务层），但批次成本层统一用成本结算日。
- CI 关闭后追加的费用按 §16 前向调整。

## 18. 历史 CI（含批量导入）操作与影响规则（纠偏，替代旧「库存>0 自动入运营」）

> 删除 V1.4 中「历史 CI 库存大于 0 时自动参与当前运营 WAC」的错误规则。历史导入 CI 是否衔接运营，必须由用户显式选择「成本初始化 / 成本衔接模式」。

### 18.1 历史批量导入 CI 默认影响范围

通过「历史 CI 批量导入」进入系统的 CI，默认只影响：

- 应付
- 付款
- 核销
- 费用
- 财务报表
- 历史成本和费用趋势分析

### 18.2 历史批量导入 CI 默认不得影响

- 当前库存数量
- 当前库存 WAC
- 销售
- 预测
- 建议采购
- 在途
- PO 未发
- 当前采购链进度

### 18.3 禁止自动判定

- **不得**根据「历史 CI 库存是否大于 0」自动决定是否进入运营 WAC。
- 历史导入 CI 与正常业务 CI **不得混用同一影响规则**。

### 18.4 成本衔接的特殊模式（未来开放，本轮不设计）

- 若未来个别历史批次需要与当前库存成本衔接，必须使用独立的「**成本初始化 / 成本衔接模式**」，并由**用户明确选择和确认**。
- 该模式仅记录为未来开放规则，本轮**不得自行设计**其实现。

### 18.5 正常业务 CI 的允许操作

正常业务 CI（非历史导入）允许：付款、核销、补费用（前向调整，见 §16/§24）、汇率换算、成本分析、利润分析；其补费用前向调整可依据当前库存影响运营 WAC（区别于历史导入 CI）。

## 19. 实时汇率异常与成本汇率兜底规则

- **严禁用「实时展示汇率」回填空缺的成本结算日快照**（两类汇率分离，§2）。
- 兜底层级：① 自动补取该日汇率 → ② 向前最近可用日近似（标记「近似兜底」）→ ③ 极端无可用汇率时**禁止自动确认成本**，转**人工确认**（手动指定汇率值+日期，标记「人工录入」）。
- 展示层降级（实时汇率异常）：库存总表当前人民币等值可暂显「—」或上次成功值，仅展示层降级，不阻断业务、不回写成本。

## 20. WAC 调整与重新确认规则

- **优先「成本调整（前向）」，不重写历史 WAC**；**重确认（重写）仅限受控异常**且生成新版本（见 §30）。
- 分情形：补录费用→成本调整（§16/§8.B）；付款冲销→只改财务不改成本；账单金额错误→小则成本调整、大且库存未大量出库则受控重确认并标注版本；汇率快照错误→按 §19 重算或成本调整。
- 任何 WAC 变更须记录：类型、原因、操作人、时间、原/新 WAC、关联 CI；历史 WAC / 历史人民币成本快照不可物理删除，仅追加版本（见 §30）。

## 21. 完整成本链路流程图

```
采购
  ↓
PI（形式发票：确定供应商 / 付款条件 / 货值基准）
  ↓
CI（商业发票：确定账单金额 / 币种 → 货值以账单金额为准）
  ↓
费用（运费 / 关税 / 商检 / 清关 / 本地杂费，多笔多币种；付款日各自存快照，见 §15.A）
  ↓
付款（分期：定金 / 尾款 / 补款；付款状态=财务维度，与成本分离；不可直改，只可冲销）
  ↓
成本确认 Cost Confirm（确定统一「成本结算日」，见 §27；纳入成本的外币按结算日折算，见 §15.B；永久保存）
  ↓
WAC（两步法增量重算本币加权平均成本；实时汇率不参与；按 国家+仓库+SKU 独立，见 §28）
  ↓
库存（以本币 WAC 流转；历史批量导入 CI 默认不回写此处，见 §18）
  ↓
人民币展示（双轨：历史人民币成本[结算日快照，稳定] ＋ 当前人民币等值[实时汇率，仅展示]）
  ↓
利润分析（基于历史人民币成本做批次 / 费用 / 趋势分析；库存总表实时值供管理层看规模）
```

> 流程中「成本确认 / WAC / 库存」使用成本结算日快照；「费用付款趋势」使用付款日快照（财务层）；「人民币展示」中的当前人民币等值使用实时展示汇率，三者分离。

## 22. 《Cost Confirm 触发规则》（成本清单确认模型，纠偏）

> 本章为成本系统最关键规则。Cost Confirm 是库存成本确定的唯一关口。

### 22.1 执行权限（谁可以执行）

- Cost Confirm 必须由具备专用权限 **`cost_confirm`** 的角色执行。
- 推荐初始授权范围：**admin**；是否授予 operator 或其他财务角色待 DB 阶段与权限模型一并确认（权限码 `cost_confirm` 本版仅作规则定义，不设计实现）。
- 无 `cost_confirm` 权限者不可触发成本确认；前端对应入口须按权限隐藏，后端须校验。

### 22.2 前置条件（必须满足才可触发）

Cost Confirm 前必须全部满足：

1. **CI 账单金额和币种已确定**（非空、合法、非停用/空币种）；CI 非草稿、非作废、非取消。
2. **实际入库数量已确定**（> 0，否则无法算单位成本）。
3. **原库存数量和原本币 WAC 已取得**（WAC 基数）。
4. **成本结算日已确定**（默认 Cost Confirm 当天，或经 §27 受控例外选定）。
5. **成本结算日所需汇率已取得或按 §19 兜底规则确认**（近似/人工并标记）。
6. **成本清单已经逐项确认**（每项标记 已纳入 / 不适用 / 允许后补 / 必须等待）。
7. **没有仍处于「必须等待」的重大费用**。
8. **CI 未作废、未取消**。
9. **不存在重复生效的成本确认**（防重复；重算走 §20 / §30）。

> 不得假设所有国家都必须存在关税或国际运费（§7 默认参与项仅为通用建议，具体以成本清单为准）。

### 22.3 成本清单状态模型

成本清单中每一类费用必须标记为以下之一：

- **已纳入本次成本**：该费用计入本批次落地成本（按成本结算日折算）。
- **本批次不适用**：该费用对本批次不适用（如某国无关税）。
- **允许后补**：确认后可追加，按 §16 前向调整。
- **必须等待，暂不可确认**：重大费用尚未确定，阻止 Cost Confirm。

只有当**不存在「必须等待」的重大费用**时，才允许 Cost Confirm。

### 22.4 必须阻止的情形（Blockers）

任一满足则**禁止** Cost Confirm：

1. CI 账单金额未确定 / 币种非法 / 为空。
2. 实际入库数量未确定或 = 0。
3. 原库存数量 / 原本币 WAC 未取得。
4. 成本结算日未确定。
5. 成本结算日汇率快照无法取得且未走 §19 兜底 / 人工确认。
6. 成本清单未逐项确认。
7. 存在仍处于「必须等待」的重大费用。
8. CI 已作废 / 已取消 / 处于不可确认状态。
9. 该 CI 已存在生效的 Cost Confirm（防重复）。

### 22.5 确认后永久锁定的状态

Cost Confirm 成功后，以下**快照与状态永久锁定，不可回溯修改**（只允许前向成本调整 / 受控重确认，见 §20 / §30）：

- 成本结算日、确认人、确认权限来源。
- 货款本币货值（按成本结算日快照折算）。
- 已纳入成本的各费用本币金额与成本结算日汇率快照。
- 成本清单逐项状态快照。
- 确认时刻的「原库存数量 + 原本币 WAC」基数（审计引用）。
- 本次入库单位本币成本、确认时刻 WAC 版本（v1，见 §30）。
- 历史人民币成本（按成本结算日快照换算）。

> 锁定的是**快照值**；WAC 本身可因后补费用按 §16/§20 前向增量变化（生成新版本，见 §30），但已确认的快照不可被覆盖或回写。

## 23. 《CI 生命周期》（纠偏）

明确 CI 从创建到永久关闭的完整生命周期。

```
OPEN（开启）
  ↓  （账单确定 + 原库存导入 + 费用陆续付款[付款日快照] + 成本清单逐项确认 + 付款分期）
Cost Confirm（成本确认，确定成本结算日，锁定快照，见 §22）
  ↓  （补费用窗口开启：仍允许按 §16 前向调整）
允许补费用
  ↓
CLOSED（关闭）
  ↓  （关闭后仍可做：付款 / 核销 / 补费用[前向，库存=0 时不溯运营] / 汇率换算 / 成本分析 / 利润分析）
```

### 23.1 OPEN（开启期）

- CI 创建、账单金额确定、库存导入、费用按付款日陆续保存快照（财务层）、付款分期进行、成本清单逐项确认。
- 此阶段可做：费用付款（保存付款日快照）、付款、付款冲销（仅财务）。
- 此阶段**尚未锁定**成本结算日快照，批次初始 WAC 尚未形成。

### 23.2 Cost Confirm

- 满足 §22.2 前置条件且成本清单无「必须等待」项后，由 `cost_confirm` 权限者触发。
- 确定成本结算日，统一折算已纳入成本，生成 WAC v1（见 §30）。

### 23.3 补费用窗口

- **Cost Confirm 之后、Closed 之前，仍允许补费用**（成本清单标记「允许后补」者，按 §16 前向成本调整）。
- 补费用不要求必须在确认前完成。

### 23.4 CLOSED（关闭）时机

CI 转 CLOSED 当且仅当满足以下之一：

1. **库存已清空且无可决补费用**：该 CI 关联批次剩余库存 = 0，且无未决/待补费用（或用户确认不再追加）。
2. **用户/系统显式关闭**：到货后经过设定观察期（如 N 天无新增费用）且用户手动标记 CLOSED；或用户基于业务判断主动关闭。

> 关闭动作本身不改变已锁定快照，仅改变 CI 状态机。

### 23.5 CLOSED 后允许的动作（纠偏重点）

- **CLOSED 不等于禁止补付款、核销或历史费用**。
- CLOSED 只代表**常规采购和成本形成流程结束**。
- CLOSED 后允许：付款（补付、冲销，仅财务）、核销、补录费用、汇率换算、成本分析、利润分析。
- CLOSED 后补录费用：
  - **当前库存 > 0 时**：可走前向成本调整（§16/§24）。
  - **当前库存 = 0 时**：只进入财务和历史成本分析，不影响运营 WAC（§24）。

### 23.6 CLOSED 后禁止 / 限制

- **禁止重新打开为 OPEN**。
- **禁止修改已锁定快照**（只允许前向成本调整 / 受控重确认，见 §20 / §30）。
- **只有「正常业务 CI」可以依据当前库存进行前向成本调整**；**「历史批量导入 CI」默认不得借此回写运营库存和 WAC**（§18）。
- **禁止将历史导入 CI 和正常业务 CI 混用同一影响规则**。

## 24. 《成本调整完善：已售库存》（纠偏，与 §8.B 一致）

### 24.1 核心原则

- **成本调整永远只影响当前库存（库存 > 0 部分）**。
- **已销售 / 已出库部分的原 WAC 与历史人民币成本快照保持不变**。
- **不得回写历史利润**：历史出库成本不可变，已入账利润不可被后续补费用修改。

### 24.2 公式（已售部分不参与基数）

补费用后的新 WAC 以「当前库存」为基数（即 §8.B）：

```
新 WAC = （当前库存数量 × 当前本币 WAC + 补录费用本币金额） ÷ 当前库存数量
```

- **当前库存数量** = 该 CI 关联批次的剩余在库数量（不含已售/已出库）。
- 已售部分既不参与分子也不参与分母。

### 24.3 库存 = 0 时的处理

- 若当前库存 = 0：补费用调整**仅记录为历史成本分析增量**，**不影响任何运营 WAC**。
- 该 CI 视为 §18 历史类（若为历史导入则本就默认不溯运营）。

### 24.4 利润分析口径

- 历史销售成本采用**销售当时的快照成本**（v1 或当时版本，见 §30），补费用不修改已售批次成本。
- 补费用若针对已售部分，只在「该 CI 总成本复盘」中体现，**不修改已入账利润报表**。
- 当前在库部分的未来出库成本按新 WAC（v_n）计算。

## 25. 汇率来源与每日唯一生效规则（Rule 1）

> 呼应 §2 成本汇率快照分离、§12 汇率自动同步。本章规定系统汇率库的「唯一性」与「取数口径」。

### 25.1 系统唯一汇率来源

- `exchange_rates` 为系统**唯一汇率来源**（呼应 §12.3）。任何业务（成本结算日快照、付款日快照、实时展示汇率取最新值）一律从该表读取，**不得**在计算时临时直接请求第三方 API（§12.4）。

### 25.2 每日唯一生效汇率

- 同一个 **`from_currency + to_currency + rate_date + rate_type`** **只能有一条正式生效汇率**。
- 第三方 API 一天可同步多次，但业务只采用系统标记为「正式生效」的结果。
- 具体如何去重、覆盖或保留同步历史，留到数据库设计阶段，本轮不设计表结构。

### 25.3 Cost Confirm 取数口径

- Cost Confirm 永远引用该日期的**正式生效汇率**，而不是 API 任意一次返回值。
- 目的：避免同一天多次同步或同一币种对存在多条记录导致成本采用不同汇率，保证同批成本结算口径一致。

### 25.4 与既有规则的关系

- 与 §2 一致：成本结算日快照锁定的是「该日生效汇率」，锁定后不随后续同步变化。
- 与 §19 互补：当某日生效汇率缺失时，按以下口径兜底，且**不得伪造目标日期汇率数据**：
  1. 若第三方成功补取目标日期**真实汇率**：该目标日期汇率可进入 `exchange_rates`，经系统确认成为该日期正式生效汇率后使用。
  2. 若使用「向前最近可用日汇率」兜底：不得伪造目标日期的汇率数据；必须保留业务目标日期；必须保留实际采用的汇率日期；必须标记为「近似兜底 / nearest-available」；汇率快照引用真实存在的历史汇率日期。
  3. 若人工确认汇率：保存人工指定的汇率值；保存人工指定或实际依据的汇率日期；标记为「人工录入」；记录操作人和原因。
- 与 §26 一致：已被业务单据引用的汇率快照永远不被后续同步覆盖。

## 26. 历史汇率重新同步规则（Rule 2）

> 明确「汇率库更新」与「已确认成本」的关系，呼应 §9 永久锁定、§13 财务/运营隔离。

### 26.1 允许更新汇率库

- 第三方 API 后续重新同步历史汇率时，**允许更新 `exchange_rates`**（含历史日期行的刷新，须遵循 §25 的唯一生效规则）。

### 26.2 已确认成本不受影响

对已生成 Cost Confirm 快照的业务：

- **不自动更新**成本结算日快照；
- **不自动重新计算**本币成本 / 本币 WAC；
- **不自动覆盖**历史人民币成本。

即：**历史汇率更新 ≠ 历史成本重算**。

### 26.3 仅受控重确认可重算

- 只有用户主动执行受控重确认流程（若未来支持，见 §20 / §30）才允许重新计算，且须生成**新版本**（见 §30），不得重写旧版本。

### 26.4 与既有规则的关系

- 与 §9「锁定后永久保存，不受后续汇率波动影响」一致。
- 与 §13「财务维度与运营 WAC 不互相回写」一致：汇率库刷新只改汇率库，不溯已锁定成本。
- 与 §25.4「已被引用的快照不被覆盖」一致。

## 27. 成本结算日确定规则（Rule 3，统一口径）

> 明确 Cost Confirm 使用哪个成本结算日，消除「为什么自动用了今天」「每次都要人工选日期」的歧义。呼应 §15.B、§22.2.4。

### 27.1 默认规则

- **默认：Cost Confirm 当天**作为成本结算日。这是常规、无需人工干预的结算口径。

### 27.2 受控例外（非日常第一默认）

用户在确认前**可以选择其他业务日期**，但必须满足：

- 前端**明确显示**所选日期；
- 受**权限限制**（仅具备特定权限者可改）；
- **记录修改原因**；
- **记录操作人**；
- **记录修改时间**。

「手动指定其他日期」是受控例外，**不是日常操作的第一默认方式**；不应让业务人员每次都人工选择日期。

### 27.3 管理员特殊修改（受控例外，非第三套常规规则）

- 管理员特殊修改只是受控例外，**不是第三套常规规则**，同样须按 §27.2 留痕（明确显示、权限限制、记录原因/操作人/时间）。

### 27.4 确认后锁定

- 成本结算日一经 Cost Confirm 即**锁定，不可直接修改**；后续如需更正，走 §20 受控重确认（生成新版本）或 §30 版本机制，不得原地改写。

### 27.5 与既有规则的关系

- 成本结算日已确定是 Cost Confirm 前置条件之一（§22.2.4）。
- 结算日确定后，纳入成本的外币统一按该日生效汇率折算（§15.B、§25）。

## 28. 多仓库 WAC 独立计算规则（Rule 5）

> 明确 WAC 的核算维度，禁止跨仓混算。呼应 §8。

### 28.1 核算维度

- WAC 永远按 **国家 + 仓库 + SKU** 独立计算。
- 各仓库各自取自身的「原库存数量 / 原本币 WAC」基数（§8.A 第二步），互不影响。

### 28.2 禁止跨仓 / 跨国合并

- **禁止跨仓库、跨国家合并计算** WAC。
- 一个 CI 涉及多个国家 / 仓库时，必须分别形成**独立成本批次或独立分配结果**，不得用单一总 WAC 覆盖多仓。
- 示例：同一个 CI 同时发往**印尼仓**与**泰国仓**，必须形成**两个独立 WAC**（各自按本国货币 LC 折算，各自演进版本，见 §30）。

### 28.3 与既有规则的关系

- 与 §8 两步法公式一致：每个「国家+仓库+SKU」维度独立跑 §8.A / §8.B。
- 与 §18 历史导入 CI 不回写运营 WAC 一致：跨 CI 维度的隔离同样适用于跨国家 / 跨仓库维度。

## 29. 多币种成本汇总规则（Rule 6）

> 规定多币种费用纳入成本时的折算顺序，呼应 §15.B、§8。

### 29.1 先折本币，再汇总，再算 WAC

所有参与成本确认的金额，**必须先分别折算成本币（LC），再汇总成本，再计算 WAC**：

- 每笔原币金额**分别保留**（付款日口径见 §15.A，批次口径见 §15.B）。
- 先分别按**成本结算日**折算为本国货币（LC）。
- 再汇总 LC 成本。
- 再计算 WAC（§8）。

示例：

```
货款 USD ─┐
运费 RMB ─┼─ 各自按成本结算日折算为 LC ─→ 汇总 LC 成本 ─→ 计算 WAC
关税 IDR ─┘
```

### 29.2 禁止的折算路径

- **禁止**：先统一换人民币（RMB）再换成本币（LC）。
- 人民币仅作派生展示货币（§4 第4条 / §10），不得作为成本归集的中间货币。

### 29.3 本币费用免换算

- 若费用本身即本国货币（LC），本币成本金额直接等于原币金额，**不需要换算**（呼应 §15.B 末）。

### 29.4 与既有规则的关系

- 与 §15.B「纳入成本的外币统一按成本结算日折算成本币」一致。
- 与 §8.A「批次本币落地总成本 ÷ 入库数量」一致：WAC 的输入必须是已汇总的本币成本。

## 30. WAC 版本与冻结机制（Rule 4 + Rule 7，统一章节）

> 规定前向成本调整后的版本演进、冻结与审计追踪。呼应 §20、§22.5、§24.4。

### 30.1 版本生成

- 第一次 **Cost Confirm 生成 WAC Version 1**（呼应 §22.5）。
- 每一次**前向成本调整**（§16 / §8.B / §20）生成新版本：**Version 2、Version 3 …**。
- 受控重确认（§20）也必须生成**新版本**，**不得重写 Version 1**。

### 30.2 版本要求

- **所有版本永久保留，不物理删除**。
- **当前库存引用最新生效版本**（v_n）。
- **历史出库 / 销售引用发生当时的成本版本**（如 v1 或当时版本），不随新版本改变（呼应 §24.4 利润分析口径）。
- **新版本不得覆盖旧版本**：前向调整是「增量生成新版本」，不是「改写旧版本」。

### 30.3 版本可追溯要素

每个版本必须可追溯：

- 来源 CI
- 调整原因
- 操作人
- 操作时间
- 原 WAC
- 新 WAC
- 影响的 国家 / 仓库 / SKU

（具体字段与表结构留到数据库设计阶段。）

### 30.4 与既有规则的关系

- 与 §22.5「确认时刻 WAC 版本（v1）」衔接：Cost Confirm 即 v1。
- 与 §24.4「历史销售成本采用销售当时的快照成本」衔接：版本即快照成本的版本维度。
- 与 §9 永久锁定一致：锁定的是版本快照，前向调整增量生成新版本，旧版本保留。
