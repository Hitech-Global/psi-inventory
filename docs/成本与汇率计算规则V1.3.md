## 0. 适用范围与禁止事项

本规则仅描述成本与汇率的计算口径、状态分离、金额分类与流程，不涉及任何实现（代码、数据库表结构、接口、字段、页面）。所有落地动作待用户确认并进入 DB 设计阶段后再行实施。

## 1. 名词与范围

- **本国货币 LC**：按 CI 目的国计价的货币，即 IDR（印尼盾）、MYR（马来林吉特）、THB（泰铢）。
- **人民币 RMB**：系统中人民币记为 `RMB`（注意：系统不使用 `CNY` 标识，全系统统一用 `RMB`）。
- **USD**：常见外币。
- **成本确认 Cost Confirm**：`cost_confirmed = 1` 的业务状态，代表库存成本已确定。
- **汇率快照 Snapshot**：在成本确认（或费用实际付款完成）时锁定的 `from → to` 汇率值 + 汇率日期 `rate_date`。
- **本币 WAC**：以本国货币计价的库存加权平均成本，存储于 `inventory.weighted_avg_cost`。
- **实时展示汇率**：系统「库存管理 → 库存总表」已存在的实时汇率功能，用于把当前本币库存货值换算成人民币，供中国团队查看当前库存规模。
- **CI 开启期 / CI 关闭期**：CI 在成本最终锁定前为「开启期」；成本确认完成且后续不再追加常规费用（或显式关闭）后为「关闭期 / 历史 CI」。

## 2. 两类汇率（必须严格区分）

### 2.1 A. 成本汇率快照（Cost Rate Snapshot）

**用途**：CI 货值成本折算、费用成本折算、落地成本、本币 WAC、历史人民币成本、历史成本趋势。

**规则**
- 在成本确认（Cost Confirm）时锁定汇率值与汇率日期。
- 锁定后**不得随市场汇率变化**。
- **不得被库存总表实时汇率覆盖**。
- **不得回写或改变已确认的本币 WAC 和历史成本**。

### 2.2 B. 实时展示汇率（Real-time Display Rate）

**来源**：系统「库存管理 → 库存总表」已存在的实时汇率功能。

**用途**：库存总表当前人民币货值、当前本币库存价值换算成人民币、管理层查看当前人民币等值。

**规则**
- 可由系统自动获取最新汇率。
- 可以动态变化。
- 只用于展示和当前估值。
- **不参与 WAC**。
- **不改变历史人民币成本**。
- **不改变 CI 成本、费用成本或付款金额**。
- **不回写本币 WAC**。

> 关键结论：两类汇率并存。成本汇率快照负责「历史与成本」口径，实时展示汇率负责「当前估值展示」口径，二者互不覆盖、互不回写。

## 3. 两种人民币金额（必须严格区分）

### 3.1 A. 历史人民币成本（Historical RMB Cost）

- **含义**：本币成本按成本确认时锁定的汇率换算出的人民币成本。
- **用途**：历史采购成本、费用趋势、批次成本复盘。
- **特点**：历史稳定，**不随实时汇率变化**。

### 3.2 B. 当前人民币等值（Current RMB Equivalent）

- **含义**：当前本币库存价值按最新实时汇率折算出的人民币金额。
- **用途**：库存总表当前人民币货值、当前库存规模查看。
- **特点**：可以动态变化，**只用于展示**，**不作为 WAC 或历史成本依据**。

### 3.3 示例

| 项目 | 值 |
|------|----|
| 本币 WAC | 220,000 IDR |
| 成本确认汇率 | 1 RMB = 2,200 IDR |
| 历史人民币成本 | 100 RMB |
| 当前实时汇率 | 1 RMB = 2,300 IDR |
| 当前人民币等值 | 95.65 RMB |

两个结果都**可以**存在，但含义不同，**禁止互相覆盖**。

## 4. 七条原基线（V1.0，全部有效）

1. **本币成本本位**：库存成本以本国货币（LC）为本位记账，人民币为派生展示货币。
2. **成本确认驱动**：库存成本在 CI 成本确认（Cost Confirm）后确定，确认前为在途/暂估状态。
3. **本币 WAC 为本**：库存流转使用本币加权平均成本 `weighted_avg_cost`，不依赖实时汇率。
4. **人民币为派生**：人民币金额是基于汇率快照换算的统计值，非唯一成本依据。
5. **落地成本口径**：落地成本 = 货款 + 参与 WAC 的费用，统一以本币归集。
6. **费用归属明确**：费用是否计入落地成本（WAC）由 `include_in_landing_cost` 决定。
7. **汇率统一来源**：所有业务汇率统一读取 `exchange_rates` 表，已确认业务采用快照锁定。

## 5. 成本确认与付款状态分离（货款未付不阻止成本确认）

- 货款可能有账期，可分多期支付。
- **货款未付清不阻止成本确认**。
- CI 账单金额确定后即可作为货值。
- 成本确认时按锁定汇率折算成本币货值。
- 应付 / 已付 / 未付属于**财务付款状态**。
- 成本确认属于**库存成本状态**。
- 两者**必须分离**。
- 后续实际付款**不得重新修改已确认库存成本**。

> 分期付款含义：定金、尾款、多次补款等支付状态仅影响财务应付/已付/未付，不改变「货值以确定即可确认成本」的原则。

---

## 6. 汇率采用时点

- **货款成本折算汇率**：在**成本确认日**快照固化（**不是** CI 建立时，也**不是**任何一笔货款的付款日）。
- **费用成本折算汇率**：按**实际付款完成日（real payment completion date）**的汇率。
- **费用确认时间** = 实际付款完成（**不是**审批通过、**不是**申请日）。

> 关于货款分期与汇率快照的定稿见 §15（货款分期付款规则）：明确采用「成本确认日」为货款汇率快照时点，分期付款日汇率差异归属于财务付款维度，不进入库存成本快照。

---

## 7. 是否参与 WAC（include_in_landing_cost）

统一命名「是否参与 WAC」。

- **默认参与**：货款 / 国际运费 / 关税 / 商检 / 清关 / 本地杂费。
- **默认不参与（待最终确认）**：退款折扣 / 内部转账 / 银行手续费 / 不绑定 CI 的通用管理费。

规则：
- 参与 WAC 的费用进入落地成本与本币 WAC。
- 不参与 WAC 的费用仅作财务记账，不影响库存成本。

---

## 8. 本币 WAC 公式（两步法）

**禁止**写成：`landing_total_cost ÷ 本次入库数量 = 最终 WAC`

### 第一步：本次入库单位本币成本

```
本次入库单位本币成本
  = 本次 CI 本币落地总成本 ÷ 本次实际入库数量
```

### 第二步：新本币 WAC

```
新本币 WAC
  = （原库存数量 × 原本币 WAC + 本次入库数量 × 本次入库单位本币成本）
    ÷ （原库存数量 + 本次入库数量）
```

等价于：

```
新本币 WAC
  = （原库存本币总成本 + 本次入库本币总成本）
    ÷ （原库存数量 + 本次入库数量）
```

**必须明确**
- 本次入库单位成本 **≠** 最终 WAC。
- 必须使用**原库存数量**。
- 必须使用**原库存本币 WAC**。
- 当前库存导入已提供本国货币 WAC。
- 实时人民币汇率**不得参与**本币 WAC 计算。
- 补录费用 / 成本调整同样适用本两步法（对「当前库存」做增量重算，见 §17、§20）。

## 9. 成本确认锁定规则（永久保存）

成本确认时锁定并永久保存以下信息：

- 原始金额、原始币种
- 汇率快照（from → to rate）、汇率日期（rate_date）
- 本币金额
- 是否参与 WAC（include_in_landing_cost）
- 确认人、确认时间
- 关联 CI、费用类型

锁定后永久保存，**不受后续汇率波动影响**。

---

## 10. 人民币成本冻结

- 人民币成本冻结的是**汇率快照**，属派生统计值，**非唯一成本依据**。
- 历史人民币成本按成本确认时锁定汇率换算，**不随实时汇率变化**。
- 当前人民币等值按实时展示汇率换算，**仅用于展示**。

---

## 11. 付款记录不可直接修改（冲销规则）

- 付款记录**不可直接改**，只可**冲销（红字）+ 重生成**。
- 冲销产生红字记录，重生成产生新正确记录。
- 冲销关联与原付款记录保持可追溯。
- 付款冲销只影响**财务付款状态**，**不触发 WAC 重算**，不修改已确认库存成本（若冲销导致货值需更正，走 §17 / §20 成本调整流程）。

---

## 12. 汇率自动获取与同步规则

- 系统通过第三方 API 自动同步汇率。
- 日常不依赖人工维护。
- 所有业务统一读取 `exchange_rates`。
- 成本计算过程中**不得临时直接请求第三方 API**。
- 支持自动补取历史日期汇率。
- 被业务采用的汇率**必须保存为快照**。
- 后续 API 汇率变化**不得影响已确认成本**。
- 库存总表现有实时汇率可使用最新自动汇率做**当前人民币等值**展示。
- 当成本所需快照日期缺失时的兜底原则，见 §19。

---

## 13. 历史 CI 财务维度与运营 WAC 存储隔离

- 历史 CI 的财务维度（人民币成本、费用明细）与运营 WAC **分开存储**。
- 运营 WAC 用于日常库存成本流转。
- 财务维度用于历史复盘与报表。
- 二者通过 CI / 批次关联，但**不互相回写**。
- 历史 CI 允许进行的操作范围，见 §18。

---

## 14. 四类金额区分总表

| 金额类型 | 汇率来源 | 是否动态 | 用途 | 是否参与 WAC |
|----------|----------|----------|------|--------------|
| 本币成本（LC） | 成本确认快照 | 否 | 库存成本、落地成本 | 是（参与） |
| 历史人民币成本 | 成本确认快照 | 否 | 历史采购成本、费用趋势、批次复盘 | 否（派生展示） |
| 当前人民币等值 | 实时展示汇率 | 是 | 库存总表当前货值、管理层查看 | 否（仅展示） |
| 付款金额（LC / 原币） | 费用=实际付款日汇率 | 否（锁定付款日） | 财务付款 | 不参与 |

## 15. 货款分期付款规则（V1.3 新增 · 写死）

**场景**：一个 CI 可能全额一次付款、定金+尾款、多次尾款、多次补款。

### 15.1 何时可参与成本确认

- **CI 账单金额确定即可参与成本确认**，不要求货款付清（与 §5 一致）。
- 货值以 **CI 账单金额**为准，与分期支付进度无关。
- 分期支付产生的应付 / 已付 / 未付为**财务付款状态**，不进入库存成本判定。

### 15.2 货款汇率快照采用时点（定稿）

- **采用「成本确认日」快照（选项 ②）**，作为货款成本折算汇率的唯一标准时点。
- **不采用「最后一笔货款付款日」（选项 ①）**：付款状态与成本状态分离，付款日汇率差异归属财务付款维度，不得回写库存成本快照。
- **「用户手动指定」（选项 ③）仅作为异常兜底**：仅当成本确认日汇率因 API 异常无法自动获取时（见 §19），允许用户在受控前提下手动指定汇率值 + 汇率日期，并标记为「人工录入」后锁定。正常情况禁止手动指定。

### 15.3 多币种货款处理

- 若 CI 账单币种 = LC（如 IDR），货款成本直接以账单金额入账，**无需货款汇率换算**。
- 若 CI 账单币种 ≠ LC（如 USD），按成本确认日快照将 USD→LC 折算为本币货值，锁定快照。
- 分期付款中各笔实际付款的币种/汇率仅用于财务收付核算，不影响已锁定的本币货值快照。

## 16. 多笔运费与多币种费用确认规则（V1.3 新增 · 写死）

**场景**：同一 CI 可能同时有 RMB 运费、USD 运费、本币运费、以及后续补开运费。

### 16.1 确认方式

- **每笔费用在其实际付款完成日各自确认**，按两步法**增量并入**落地成本与本币 WAC。
- **不要求等全部费用完成后再统一成本确认**。
- 费用确认与 CI 货值确认相互独立：货值可在 CI 账单确定时先确认；运费/费用在各自付款完成时陆续并入。

### 16.2 多币种运费汇率

- 每笔运费按其**自身实际付款完成日**的汇率快照折算为本币（USD 运费用付款日 USD→LC；RMB 运费用付款日 RMB→LC；本币运费无换算）。
- 不同币种、不同付款日的运费各自锁定自己的汇率快照，互不影响。

### 16.3 与 WAC 增量重算

- 每次新费用确认后，按 §8 两步法对「当前库存」做增量重算：
  `新 WAC =（原库存本币总成本 + 本次费用本币金额）÷（原库存数量 + 本次入库数量）`。
- 若费用发生在不同批次入库之间，以「当前库存数量 + 当前 WAC」作为原值基数。
- CI 关闭后追加的费用，按 §17（补录费用）处理。

## 17. 补录费用规则（CI 完成后追加费用，V1.3 新增 · 写死）

**场景**：CI 已完成 / 成本已确认后，货代补开费用、补关税、补仓租、补其他费用。

### 17.1 主规则（推荐采用）

- **允许进入原 CI 成本**，但**不回溯重写历史**，采用**「成本调整（前向）」**方式：
  - 新增一笔「成本调整」记录，关联原 CI。
  - 按 §8 两步法对**当前库存**做增量重算，生成新 WAC。
  - 已出库 / 已销售部分的原 WAC 与历史人民币成本快照**保持不变**（历史稳定，不随调整变化）。
  - 仅影响后续库存与未来出库成本。
- 即原则：**前向调整，不回溯历史**。

### 17.2 备选分支（不允许进原 CI 时）

- 若费用被判定为「不计入该 CI 落地成本」（如与本次到货无关、或属于期间性管理费），则：
  - 进入**独立的后续费用 / 期间费用科目**，**不参与该 CI 的 WAC**。
  - 仅作财务记账与费用分析，不触发 WAC 重算。
- 该分支为兜底，默认优先走 17.1 主规则。

### 17.3 是否参与 WAC

- 补录费用同样适用 §7 的 `include_in_landing_cost` 判定：参与类（关税/仓租/运费类）进 WAC；不参与类（退款折扣/内部转账/银行手续费等）仅财务记账。

## 18. 历史 CI 操作许可规则（V1.3 新增 · 写死）

**场景**：CI 已关闭 / 已成为历史单据。

### 18.1 允许的操作（全部允许）

历史 CI 允许进行以下操作，均**仅落在历史 CI 财务维度**：

- **做付款**：对历史 CI 关联货款/费用补付、付款冲销（仅财务维度）。
- **做核销**：付款与应付的核销匹配。
- **做费用**：补录费用（按 §17 前向调整，不回溯历史库存）。
- **做汇率换算**：用历史快照或补取的历史汇率做成本/人民币换算用于分析。
- **做成本分析**：批次成本复盘、费用趋势、利润分析。

### 18.2 禁止影响的对象（硬约束）

历史 CI 的任何操作**不得影响**：

- 当前 `inventory.weighted_avg_cost`（运营 WAC）
- 补货建议 / 采购建议（replenishment_suggestions）
- 订单预测
- 当前在库库存数量与价值
- 其他未关闭 CI 的成本

即：历史 CI 的财务操作只产生**财务维度结果 + 报表**，绝不回写运营 WAC 与供应链预测。

## 19. 实时汇率异常与成本汇率兜底规则（V1.3 新增 · 写死）

**场景**：API 当日失败、历史日期无汇率、第三方异常。

### 19.1 总原则

- **严禁用「实时展示汇率」（库存总表实时汇率）回填空缺的成本汇率快照**——两类汇率分离（§2）。
- 成本确认所需快照来自 `exchange_rates`（自动同步），缺失时按以下兜底层级处理。

### 19.2 兜底层级（依次尝试）

1. **自动补取**：系统支持补取历史日期汇率（§12），先尝试自动回源第三方补该日汇率；成功则正常锁定快照。
2. **最近可用日近似**：若自动补取仍失败，采用**向前最近一个已同步成功的汇率日**作为快照，并标记该快照来源为「近似兜底 / nearest-available」，记录原缺失日期。
3. **人工确认（极端）**：若连近似汇率都无法获得（极端异常），**禁止自动确认成本**；转为**人工确认**——用户手动指定汇率值 + 汇率日期（即 §15.2 选项 ③），人工确认后锁定快照并标记「人工录入」。

### 19.3 展示层降级（不影响成本）

- 若实时展示汇率异常，库存总表「当前人民币等值」可暂显示「—」或上次成功值，**仅展示层降级，不阻断业务、不回写成本**。
- 成本汇率快照的缺失与展示汇率异常相互独立处理。

## 20. WAC 调整与重新确认规则（V1.3 新增 · 写死）

**场景**：成本确认后，出现补费用、付款冲销、账单错误，需重新确认成本。

### 20.1 总原则

- **优先采用「成本调整（前向）」，不重写历史 WAC**。
- **重确认（regenerate / 重写）仅限受控异常**，且必须留版本痕迹。

### 20.2 分情形处理

| 情形 | 处理方式 |
|------|----------|
| 补录费用（CI 关闭后追加） | 成本调整（前向），见 §17。已出库部分历史不变。 |
| 付款冲销 | **不改成本**，仅财务付款状态（§11）；若冲销导致货值需更正，走成本调整。 |
| 账单金额录入错误（货值错） | 影响小 → 成本调整；影响大且库存尚未大量出库 → 允许在受控条件下**重新确认**（re-confirm），标注成本版本（v1/v2），原版本快照保留可查。 |
| 汇率快照错误（非展示汇率） | 按 §19 兜底层级重算快照；若已锁定错误快照，走成本调整或受控重确认。 |

### 20.3 版本与可追溯

- 任何 WAC 变更（调整或重确认）必须记录：变更类型、原因、操作人、时间、原 WAC、新 WAC、关联 CI。
- 历史 WAC / 历史人民币成本快照**不可物理删除**，仅追加新版本。

## 21. 完整成本链路流程图（V1.3 新增）

```
采购
  ↓
PI（形式发票：确定供应商 / 付款条件 / 货值基准）
  ↓
CI（商业发票：确定账单金额 / 币种 → 货值以账单金额为准）
  ↓
费用（运费 / 关税 / 商检 / 清关 / 本地杂费，多笔多币种，按付款日各自确认）
  ↓
付款（分期：定金 / 尾款 / 补款；付款状态=财务维度，与成本分离；不可直改，只可冲销）
  ↓
成本确认（Cost Confirm：锁定货款汇率快照=确认日、费用汇率快照=付款日；永久保存）
  ↓
WAC（两步法增量重算本币加权平均成本；实时汇率不参与）
  ↓
库存（以本币 WAC 流转；历史 CI 操作不回写此处）
  ↓
人民币展示（双轨：历史人民币成本[快照，稳定] ＋ 当前人民币等值[实时汇率，仅展示]）
  ↓
利润分析（基于历史人民币成本做批次 / 费用 / 趋势分析；库存总表实时值供管理层看规模）
```

> 说明：流程中「成本确认」「WAC」「库存」使用**成本汇率快照**；「人民币展示」中的「当前人民币等值」使用**实时展示汇率**，二者分离。历史 CI（关闭期）的付款/核销/费用/汇率换算/成本分析全部允许，但结果只进财务维度，不溯及运营 WAC 与预测。
